Code rules read JavaScript and TypeScript more as ESLint does. A `/* global x */` comment no longer makes `x` one of the globals a rule lists (so `foo(); /* global foo */` is no `Function` call). `using` and `await using` in a `for…of` head bind in the loop. A name written with `\u` escapes is the same name as its plain spelling for scope lookups. A `file.content` regex on a JavaScript, TypeScript or Vue file reads past a leading byte-order mark. `static`, `get` and `set` before a member name on the next line stay modifiers, as espree and TypeScript parse them. Rule documents gain a `toPrecision` transform and `value: { name: true, … }`, which tests what a node names with its escapes decoded ([DSL reference](docs/code-rule-dsl-reference.html)).
