Installing Rerail from Pi's package gallery (`pi install npm:@neralabs/rerail`) and then running `/rerail-start` no longer loads Rerail twice. Set-up replaces the `npm:@neralabs/rerail` entry in `~/.pi/agent/settings.json` (at any version, and in the `{ "source": … }` form with its filters kept) with the managed install, in its place, and says so, so Pi stops failing to load the second copy on its tools and `rerail update` governs the version Pi loads. It does so on the first set-up, when `/rerail-start` runs again in a repository already set up and Pi was connected, and on every `rerail update`; set-up that leaves Pi out with `--agents` leaves a gallery-only Pi as it is. An entry for the managed install already in Pi's settings keeps its place and filters, and the npm entry is removed beside it. Other `npm:` entries, rule packs included, stay, and `rerail install --remove` of the managed install (before any set-up, the running package) takes an `npm:@neralabs/rerail` entry out too; removing a checkout registered with `--root` leaves it. When OMP also has its own plugin install of Rerail (`omp plugin install @neralabs/rerail`), which it loads beside set-up's extension link, set-up's summary, `rerail install` and every `rerail update` say to remove it with `omp plugin uninstall @neralabs/rerail`; set-up changes nothing in OMP's plugin folder.
