A coding agent's Rerail MCP tools now reach only the repository its checkout belongs to, and the checkouts inside its own: `repositories_list` lists that repository alone, any other named in a read or a write is refused, and its history (sessions, transcript events, work links, audits, violations, and rule activity and the rules it lists) is scoped there, another repository's session or audit answering as one that does not exist. In its own repository's transcripts an agent gets every tool output withheld, the input of a call that names a hidden or secret-like path (`cat .env`, `cat {.env,.npmrc}`, a `..data/` mount) or is too deep or large to read whole, and the whole payload of any event kind Rerail does not know; `rerail rules evidence` names such a call by its tool alone and lists no standards file Git ignores. A finding in a file named like one holding secrets (`secrets.yaml`, `credentials.json`, under `.aws/`) reaches an agent by rule and place only, in the steer and in the audit and violation lists: its message, variables and fix stay in the dashboard. Within its reach an agent changes a repository's attachments and settings only while it is not set up (or to add a rule it creates, or its copy of a By Rerail rule), and edits or deletes a rule created by you only where no other repository runs it. Its Rerail tools may no longer turn Follow .gitignore off, change the ongoing audit settings (`rerail settings`), or change the status line preferences; those are the dashboard's and `/api`'s. This scopes what an agent's tools reach; an agent with a shell runs as you.
