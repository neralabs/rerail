# Rerail rule pack: React, candidates

The ports in `rules/` here are still being evaluated: scored against the tools' expected findings and reported, never
gated and never shipped. This file is not published; the pack's [README](../README.md) covers the rules it ships.

## Rule details

What each rule matches beyond its one-line description: exact matching, edge cases, upstream settings and known divergences.

### `react-hooks-immutability`

Ports the React Compiler's immutability checks in the functions it compiles at its defaults (infer mode: a capitalised function with valid props that creates JSX or calls a hook, a `use…` function that does, or a `memo`/`forwardRef` callback, in a file with a top-level component or hook). It reports a store, `delete` or update through a component's props, a hook's arguments or a hook's result (`useRef` and ref-like `…Ref.current` aside), in the body or once per variable in a function directly inside it; a reassigned parameter that a nested function reads, at the first reassignment; a variable read before its declaration by a function a hook or JSX receives first, at the first read (a `useCallback`'s dependency first); a function handed to a hook or JSX that reassigns or changes a local variable, where it is first handed on, with the first reassignment for the component's one such function or the last function of a `useMemo` controller object; and a change to a global or module value in the body or in a function it calls or passes to a non-hook call. Known limits: the compiler's data flow is approximated, so it misses mutations of values frozen by an earlier hook argument, effect dependency or JSX use, array methods on memoised arrays, functions that inherit a mutation from another function, and references through deeper closures; a component the compiler abandons on an internal invariant (a nested destructuring into partly captured variables) is still checked.

### `react-hooks-refs`

Port of eslint-plugin-react-hooks 7.1.1 react-hooks/refs, the React Compiler's ValidateNoRefAccessInRender as the plugin runs it (compilationMode infer, only in a file with a top-level component- or hook-named function or variable, or a default-exported anonymous function). It analyses the render of the functions the compiler compiles: component-named functions that create JSX or call a hook with at most a props and a ref-named parameter and no last return of a non-node; hook-named functions that do; memo and forwardRef callbacks; none inside a class or another compiled function, with useMemo callbacks and immediately invoked functions read as part of the render. A ref is a `useRef()`/`React.useRef()` binding or a local named `ref` or `…Ref` whose `.current` is read. It reports, at the place the compiler does and as often: writes to `ref.current` (or a property of it, `+=` and `++` twice) outside the first write inside an `if (ref.current == null)` / `if (!ref.current)` guard; the ref's value (through property chains, casts, ternaries, logical expressions and variables holding it) used in JSX, returned, passed to a call, tested, operated on (dead `const`s excepted), stored in a property, called, a method called on it (twice), optionally chained, or put in an object or array literal, with the literal reported again where it is passed on (at the literal when it mixes refs or holds values whose origin the compiler has lost); a ref, or a function or literal holding one that reads or writes a ref, handed to a function that may call it (not a hook, but useState's and useReducer's initialisers, and not where the call returns a ref); and every property of a local whose property is passed as a JSX `ref` (`ref={props.innerRef}`), which the compiler then types as a ref, read after that attribute or by the element holding it, or anywhere when nothing else errs. Known limits: a function reading refs called during render, nested literals passed on, values flowing through a useMemo result, longer optional chains (`ref.current?.a()?.b`) and the compiler's second pass after other errors are reported only in part; a file the grammar cannot parse is not evaluated.

### `react-react-in-jsx-scope`

Port of eslint-plugin-react 7.37.5 react/react-in-jsx-scope (pragma React). A JSX opening element or fragment is reported when no `React` binding is visible: none declared at the top level (import, var/let/const, function), in an enclosing block's own declarations, or as an enclosing function's parameter.
