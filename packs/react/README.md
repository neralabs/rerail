# Rerail rule pack: React

The pack ships 30 eslint-plugin-react and 8 eslint-plugin-react-hooks rules, ports of eslint-plugin-react 7.37.5 and
eslint-plugin-react-hooks 7.1.1; three more ports are candidates ([candidates/README.md](candidates/README.md)). A port starts in `candidates/rules/` and moves to `rules/` and
`pack.json` once it passes the conformance check ([conformance/README.md](../../conformance/README.md#the-gate)), which
CI runs on every port. Every port is scored against the plugins' own findings on the
plugins' test cases and on their rename variants (`holds-under-rename`), and against the labelled lines of the plugins'
real-code samples ([docs/upstream.md](../../docs/upstream.md#samples)), through the engine's production workspace
path. The conformance check (`--check`, run in CI) scores the test cases and the samples: it gates the ports in
`rules/` and reports the candidates without gating them. The hooks plugin's React Compiler rules have no test cases of
their own here (upstream tests them through the compiler's fixtures), so their test-case answers are the plugin's
findings on the rules-of-hooks and exhaustive-deps cases, and the samples carry them; the four of them those cases never
report on (`error-boundaries`, `purity`, `set-state-in-render`, `static-components`) ship off, as `upstream-status` asks.

Most samples come from the React test set: 738 real files from 57 MIT and Apache-2.0 repositories, each at the commit
that introduced a violation of one rule, labelled with ESLint's findings for that rule (the plugins at their defaults);
631 hand-fixed copies, clean for the rule; and 99 files whose own `eslint-disable` comment silences the rule, so a port
that ignores the comment reports on a line no label marks. It holds no Flow file, no JavaScript only a TypeScript parser
reads, and no file whose JSX belongs to another library. `node --import tsx conformance/languages/cli.ts --pack react
--samples` scores the samples alone.

Every rule runs on JavaScript and TypeScript files whose JSX runtime is React or not known; a file whose JSX belongs to
another library is skipped. The runtime is the file's `@jsxImportSource` pragma when it names React, Emotion
(`@emotion/react`) or Theme UI (React) or Preact, Solid, Vue, Stencil, Hono, Qwik, Inferno, Mithril or Hyperapp (another
library), or its `@jsx` pragma when that names `React`; else an `h` or `createElement` imported from Stencil, Preact,
Vue, Solid, Hyperapp or Mithril (another library); else its nearest `package.json`: React when it depends on react,
react-dom, react-native or next and on none of vue, @stencil/core, preact, solid-js, @builder.io/qwik, inferno or
mithril, another library in the reverse case, unknown otherwise. `react-in-jsx-scope` also skips files whose `@jsx`
pragma names another factory (Emotion's `jsx`, for one): the plugin then asks for that factory in scope, which the
port does not check.

The pack follows the [pack structure and validation contract](../../docs/pack-format.md): it is checked by
`npx vitest run test/engine/catalog/packs.test.ts -t "pack react"`.

| Path | What |
|---|---|
| `pack.json` | The pack (`rerail.rule-pack/v1`): its match definition and the 38 rules it ships, with an example each rule catches and one it lets pass |
| `conformance.json` | Every port (shipped under `rules/`, or a candidate under `candidates/rules/`): its upstream tool and rule, how findings compare and the capabilities it exercises; the pinned tools. Written by `candidates/build.mjs` |
| `upstream/<tool>/` | The plugin's copied tests (`tests/`), the cases extracted from them (`fixtures/`, their rename variants under `fixtures/renamed/`), its expected findings (`fixtures.expected.json`), the generator (`generate.mjs`, sharing `upstream/common.mjs` and `scripts/pack-data/eslint-expected.mjs`), and the lock naming its real-code samples (`samples.lock`, fetched by `npm run fixtures:pull`) with their sources and licences (`SAMPLES.md`); `UPSTREAM.md` lists the fixtures Rerail wrote beside them (`common.mjs` `AUTHORED`): files of other JSX libraries, which the plugins report and the ports skip, and React files whose JSX goes through Emotion, which both report |
| `divergences.json` | Where the ports and the expected findings disagree by design: the plugins' findings on the authored files of other JSX libraries, and sample lines under an `oxlint-disable` comment (or an `eslint-disable` naming another plugin's same-named rule), which silence the port as they silence Oxlint and not ESLint |
| `licenses/<project>/` | The upstream licence and `UPSTREAM.md`, per upstream repository: its source, the patterns of the files taken and how (each file's provenance is `provenance.json` in the tool's test-data archive) |
| `rules/` | The shipped ports' code-rule documents: written by `candidates/build.mjs` from `candidates/specs.mjs`, or by hand for the ports `specs.mjs` lists in `HAND_WRITTEN` |
| `candidates/` | Ports still being evaluated, scored but never shipped: the code-rule documents (`rules/`, written by `build.mjs` from `specs.mjs`, or by hand for the `HAND_WRITTEN` ports); `probes/` holds the hand-labelled React fact probes |
| `candidates/README.md` | What each candidate is waiting on and its rule details; not published |

Taking a new snapshot is a maintainer deriving the pack's test data from its pins and publishing it
([docs/upstream.md](../../docs/upstream.md#take-a-new-snapshot)); a pull request carries it only as a publish request
under `upstream/<tool>/publish/`. The recipe (`scripts/pack-data/recipes/react.ts`) runs each plugin's `generate.mjs`
against the pinned tools (eslint 9.39.5, @typescript-eslint/parser 8.70.1, typescript 5.9.3) and the plugins' upstream
checkouts. The fixtures Rerail wrote (`UPSTREAM.md`) are authored: a change to them is staged into `publish/` with the
derived data.

```sh
npm run fixtures:derive -- --pack react                                     # both plugins
npm run fixtures:derive -- --pack react --tool eslint-plugin-react-hooks    # one
npm run fixtures:stage -- --pack react --tool eslint-plugin-react-hooks     # copy what changed into upstream/eslint-plugin-react-hooks/publish/
```

Rewriting the rule documents and `conformance.json` after editing `candidates/specs.mjs`, then scoring one rule with
every false positive and false negative printed:

```sh
node candidates/build.mjs
node --import tsx conformance/languages/cli.ts --pack react --rule react-jsx-key --fixtures
```

## Rule details

What each rule matches beyond its one-line description: exact matching, edge cases, upstream settings and known divergences.

### `react-button-has-type`

Port of eslint-plugin-react 7.37.5 react/button-has-type with button, submit and reset allowed. Reports a `<button>` with no `type` attribute (looked up case-insensitively, as jsx-ast-utils getProp does) or whose first `type` value is not a literal button/submit/reset. Each leaf of a conditional `type` is checked, and a non-literal leaf is reported at itself. The same applies to `React.createElement('button', props)` with the default pragma.

### `react-hooks-error-boundaries`

Port of eslint-plugin-react-hooks 7.1.1 react-hooks/error-boundaries (the React Compiler's JSX-in-try validation), default compiler settings (`compilationMode: 'infer'`). Every JSX element and fragment, children and attribute values included, built in the body of a `try` that has a `catch` is reported at its start; a `catch` body counts only when that `try` itself sits in an outer `try` body. The element must be built directly in a function the compiler compiles: a function declaration or variable-declared function named like a component (`X…`, with 0–2 parameters, a first parameter not typed as a primitive, array, tuple, function or literal, a second one named `…ref`/`…Ref`, and a last `return` that is not an object, function, class, `new` or bare `return`) or a hook (`useX…`), or the callback of `memo`/`forwardRef`, which renders JSX or calls a hook, is in no class and no other compiled function, in a file that declares a component- or hook-named function at its top level or exports an anonymous one by default. Not reported, as upstream: JSX in a nested callback, a `finally` block, a `try` without `catch` or a `yield`; JSX whose value is discarded (an expression statement, `void`, or a variable that is never read, or read only by `yield` or by an unread nested function); and every element of a function that reads a class it declares or has a `catch` with a destructured parameter, where the compiler bails out. Known limits: other dead stores the compiler's dead-code elimination removes are still reported, and the other compiler bail-outs are not modelled.

### `react-hooks-exhaustive-deps`

Port of eslint-plugin-react-hooks 7.1.1 react-hooks/exhaustive-deps, default options (no `additionalHooks`), one clause per report the rule makes. It analyses useEffect and useLayoutEffect (always), and useCallback, useMemo and useImperativeHandle (when given dependencies), bare or as `React.*`, whose callback (the first argument, useImperativeHandle's second; through `as` casts and parentheses) is an inline function or the name of a function declared in the scope the hook runs in. A dependency is a name the callback reads that is declared in the function the hook runs in, outside the callback, as a path: `props.a.b` up to a call (`props.a()` needs `props`), a `.current` (`ref.current` needs `ref`) or an assignment target. A path is covered by a listed path that equals it or a prefix of it (`a?.b` reads as `a.b`). Stable values need no entry: useRef, useEffectEvent, `const` string/number/null literals, the second of two names a useState, useReducer, useActionState or useTransition result is destructured into (unless reassigned), and a function declared at the top of the component that reads none of its other values. At the dependency array, one report per hook, by upstream's precedence: a missing dependency; else an unnecessary one (useCallback, useMemo and useImperativeHandle: a listed path no dependency needs, or one under another listed path; effects: an outer-scope or global path, or one ending in `.current`); else a duplicate. Also reported: dependencies that are not an array literal (at the dependencies, beside any missing one), a spread, a literal, or another expression in the array (at the element; `a?.[b]` reads as the path `a.b`, as ESTree does), a useEffectEvent function the callback reads listed in the array, each first assignment from the callback to a value of the component (at its right side; it suppresses the hook's other dependency reports), the last `ref.current` an effect's returned cleanup reads for a ref no code assigns `.current` to, an effect without dependencies that reads a useState setter outside nested functions, a listed top-level object, array, function, class, element, `new` or regex value of the component that every render rebuilds (at its declaration, once per hook, when the array has no other problem), an async effect callback, a hook without a callback, useCallback or useMemo without dependencies, a callback that is neither a function nor a name (or a parameter's name), and a callback name that declares no function. Not matched: the order upstream reads scopes in, for a value assigned twice in one callback in sibling scopes, and which cleanup read of a ref it keeps when nested functions interleave (both approximated by source order); a useEffectEvent function listed by a hook whose callback does not read it (upstream reports it once any earlier hook's callback has); a file the grammar reads with syntax errors is not analysed (the analysis reads bindings).

### `react-hooks-globals`

Port of eslint-plugin-react-hooks 7.1.1 react-hooks/globals (the React Compiler's "Cannot reassign variables declared outside of the component/hook"), default compiler options. Reports, at the name, an assignment (`=`, an arithmetic or bitwise `op=`, a name a destructuring assignment writes; not `++`, `--` or `&&=`/`||=`/`??=`, which the compiler does not store) to a name not declared in the function being compiled: a module variable, an import, an undeclared global, or a variable of an enclosing function such as a test's `describe`/`it` callback. The compiled function is the one the eslint plugin compiles: a function declaration, function expression or arrow (never a method or one inside a class) named `X…` through its declaration or `const` declarator, with at most a props parameter whose type is not a primitive, array, tuple, function or literal type plus a `…ref`/`…Ref` one, whose last return is not an object, function, class, `new` or BigInt, or named `useX`, or the callback of `memo`/`forwardRef` (bare or `React.*`), that has JSX or a hook call in its own body and is not inside another such function; and only in a file whose top level declares a component- or hook-named function (the plugin skips other files). The assignment counts when it runs in render: in the compiled function's own body, an IIFE in it, or a `useMemo` callback; in a function passed to a call or `new` made there (directly, inside an array or object literal, or as a ternary branch) unless the callee is a hook, a state setter from `useState`/`useReducer`/`useActionState`/`useOptimistic`, or a builtin the compiler types as only reading its arguments (`console.*`, `Math.*`, `Object.keys`…); in a function child of a named element the function returns; or in a `const` or declared local function that a later statement of the body calls by name. Code after a return, throw, break or continue of its statement list is skipped. Known limits, all misses: a nested component used as a JSX tag, a local function declared inside a block, by `let`, or reached through another closure (the compiler's alias analysis), a function passed through `.call`, a component that returns an object or nothing before a last return that does not end its body, and TypeScript-annotated `.js` files ESLint reads with Hermes. One known false positive: code after a `try` whose block starts with a `throw`, which the compiler leaves unreachable.

### `react-hooks-purity`

Port of eslint-plugin-react-hooks 7.1.1 react-hooks/purity, the React Compiler's check for the three functions it types as impure: `Date.now()`, `Math.random()` and `performance.now()` (also `Math['random']()`), on the unshadowed globals, reported at the call. It follows the compiler's lint run: only a file with a top-level component or hook declaration is compiled (not one with a TypeScript `<T>x` assertion, nor a JavaScript file with an import attribute, which the compiler's parsers reject), and in it each outermost function the infer mode compiles: an `X…` function declaration or function assigned to a `const`/`let`/`var` that calls a hook or creates JSX outside nested functions, takes at most a props and a ref parameter, and whose last return is not an object, function, class, `new` or bare `return`; a `useX…` one that calls a hook or creates JSX; and a memo/forwardRef callback. A call is reported when it runs as render: in that body or a default parameter, or in a `useMemo` callback or immediately invoked function there; in an inline callback that render passes to a call (not a hook, a `console`/`Math` method, `Object.keys`/`values`/`entries`/`fromEntries`, another builtin the compiler types as only reading its arguments, or a useState/useReducer setter; `map`, `sort`, `then`, `setTimeout` and `new Promise` count, also through arrays, objects, conditionals and casts), renders as a JSX child or calls a method on; and in a local function of render that render calls, passes as such an argument, renders as a child or tag, reads a property of or hands to `useMemo`, that such a callback calls, that a handler nested in such a callback calls with one of the callback's own non-literal values, or that reaches itself through calls (a `requestAnimationFrame` loop). Calls in effects, event handlers, `useState` initializer functions, `useCallback` callbacks and class components are not reported. Known limits, all misses: an alias (`const r = Math.random`), `globalThis.Date.now()`, a function a `map` callback returns (alone or in an object) and render renders, a handler in a JSX attribute that calls a local function with a prop, and a function assigned after its `let` declaration.

### `react-hooks-rules-of-hooks`

Port of eslint-plugin-react-hooks 7.1.1 react-hooks/rules-of-hooks. A hook call (`use`, `useX`, `Namespace.useX`) is reported at its callee when it runs, in a component or hook (a function named `X…`/`useX`, or the callback of memo/forwardRef), conditionally (if/conditional/logical/switch/catch/default branch, or after an earlier return); in a class method or field; in another named function; at the top level; in an anonymous callback inside a component or hook; in a loop; in an async component or hook; and `use` inside try/catch. A function a component or hook creates with `useEffectEvent` (`const onX = useEffectEvent(...)`) is reported at each reference (a call, an argument, a dependency-array entry, an `{ onX }` shorthand property) outside the arguments of a `useEffect`, `useLayoutEffect`, `useInsertionEffect` or `useEffectEvent` call, and a `useEffectEvent(...)` call that is neither assigned nor a statement of its own (passed as a prop or argument) is reported too. ESLint's code-path analysis is approximated syntactically.

### `react-hooks-set-state-in-effect`

Port of eslint-plugin-react-hooks 7.1.1 react-hooks/set-state-in-effect (the bundled React Compiler's validateNoSetStateInEffects, default config). It checks functions the compiler compiles in `infer` mode: a function declaration or `const` function named like a component (`X…`, 0–2 params with a props type that is no primitive, array, tuple or function, a second param named `…ref…`, last return a node) or hook (`useX`), or a memo/forwardRef callback, not inside a class or another component or hook, in a file with a top-level component- or hook-named function or an anonymous default-exported function. In the inline callback of useEffect, useLayoutEffect or useInsertionEffect (bare, imported from react/react-dom under any alias, or `React.*`) it reports the first synchronous call, at its callee, of a `useState` setter (also through a constant alias) or of a component-level function (plain, `useCallback` or `useEffectEvent`) that itself calls one synchronously; a callback passed by name is reported at the name. Calls in nested functions, setters or functions declared after the effect or referenced before their declaration (hoisted context variables), and calls with a spread first argument do not count; finally blocks and try statements without a catch are skipped. Following the compiler's ref allowance, a setter call whose first argument may be ref-derived (a `useRef` result, a `…Ref`/`ref` name read through `.current`, a JSX `ref` value, a value read off one, a callback-local variable computed from or written under one, a call of a local function returning one) ends the check for that effect, and one whose nearest controlling test (its branch's test, or the exits of the nearest earlier statement that may leave) or enclosing try block may be ref-derived is skipped; both are judged generously, so the port misses rather than reports where upstream's data flow is finer (an earlier setter call skipped only by such a test still hides later ones unless the test reads a ref directly). Functions the compiler gives up on report nothing: a TanStack Table/Virtual hook, React Hook Form's `watch`, a spread argument to a hook or createElement, a `this` parameter, a catch parameter read in a closure, or a conditional or optional chain in a try block of a useMemo callback. Known misses: an inline `useCallback(...)` effect argument, `useMemo(() => fn)` values, other silent compiler bail-outs.

### `react-hooks-set-state-in-render`

Port of eslint-plugin-react-hooks 7.1.1 react-hooks/set-state-in-render (the React Compiler's ValidateNoSetStateInRender, default compiler options). A setter is the second name destructured from `useState` (bare when unbound, imported from `react` under any alias, or `React.useState`) and never reassigned; a setter function is a local function declaration, arrow or function expression whose own body calls a setter unconditionally. It analyses the functions the compiler's infer mode compiles in a file whose top level declares a component, a hook or a default-exported function: a function named `X…` (with zero parameters, one non-rest parameter or a second parameter whose name holds `ref`/`Ref`, no primitive-typed props and no return of an object, function, class, `new` or nothing) or `useX…`, or the callback of `memo`/`forwardRef` (bare or `React.*`), outside classes and outside another such function that calls a hook or creates JSX. It reports, at the callee, a call of a setter or setter function that runs on every render of that function: at its top level or inside expressions and JSX, but not inside if/loop/switch/try/conditional branches, the right side of `&&`/`||`/`??`, an optional chain, a default value, a bare block, or after an earlier statement holding a `return`. It reports every such call anywhere in the inline synchronous callback of `useMemo` (bare when unbound, imported from `react`, or `React.useMemo`) whatever its branch, and an inline async `useMemo` callback that calls one unconditionally at the callback itself. Known limits (each a miss, never a false report): setters aliased through another variable, chains of setter functions beyond one level, immediately invoked functions, `useMemo` given a function by name, a setter call in an `if` condition, a `switch` case that always runs or a bare block, and components whose earlier return of an object is not their last return.

### `react-hooks-static-components`

Port of eslint-plugin-react-hooks 7.1.1 react-hooks/static-components (the React Compiler's ValidateStaticComponents, default compiler settings). Reports a capitalized identifier JSX tag (`<C />`, not `<a.B />`) in the body of a function the compiler compiles: a function declaration or `const` arrow/function named like a component (at most two parameters, the first not a rest parameter nor annotated with a primitive, literal, array, tuple or function type, the second a name containing `ref`; last return not an object, function, class, `new` or bare `return;`) or a hook (`useX`), or a `memo`/`forwardRef` callback, that renders JSX or calls a hook and is not nested in another such function or a class; only in files with a top-level component- or hook-named function declaration or `const` function, as the plugin's file gate requires. The tag must be a local of that function whose value is created during render: a call (not a tagged template), `new`, a function expression or arrow, an inner function declaration, through parentheses, `!`, the last expression of a sequence, either branch of a conditional or `&&`/`||`/`??`, another such local, a destructuring or parameter default, or a plain `=` assignment (one inside a loop only for JSX in that loop). `useMemo`/`React.useMemo` with an inline callback and an array (or no) dependency list, and a zero-argument IIFE, are inlined as the compiler inlines them: their result counts only when the callback returns such a value, and JSX directly in that `useMemo` callback is checked; a `useMemo` whose dependency list holds a conditional, logical or optional-chain expression right after an inlined call in the same straight-line run of statements is not inlined (a call, and its callback unchecked). Not reported, as the compiler does not track them: casts (`as`, `satisfies`), `await`, member reads, destructured values, JSX in other callbacks or IIFEs, a variable a closure captures that is also reassigned, a name a closure (or, for an inner function declaration, any earlier statement) references before its declaration, and JSX whose value is discarded (an expression statement or an unused variable, through parentheses, JSX nesting and array or object literals), which dead-code elimination drops. A function with a destructured `catch` parameter is skipped, as the compiler aborts on it. Known limits: flow-insensitive, so a dynamic initializer overwritten on every path (`let C = make(); C = A;`) is still reported; other compiler aborts (a referenced inner class declaration) are not modelled; a file the TypeScript grammar cannot parse is not analysed.

### `react-iframe-missing-sandbox`

Port of eslint-plugin-react 7.37.5 react/iframe-missing-sandbox (no options). Reports, at the `<iframe>` opening tag or at the call, an `<iframe>` with no `sandbox` attribute (a spread does not count) and a `React.createElement('iframe', props)` (the default pragma, or a `createElement` imported or destructured from React) whose props are not an object literal with a `sandbox` property (a quoted `'sandbox'` key does not count, as upstream reads only identifier keys). A string `sandbox` value (every JSX `sandbox` attribute, the first `sandbox` property of the props) is split on spaces and each trimmed token outside the allow-* list upstream accepts is reported once, naming the token; a value holding both allow-scripts and allow-same-origin is reported once more. Expression values (`sandbox={"…"}`), template literals and non-string values are not checked, as upstream. Known limits: a JSX value with an HTML entity (`&amp;`) or a JS string with an escape sequence has its unknown tokens left unreported (the both-flags check still reads the decoded value), and a `/** @jsx h */` pragma comment is not read, so `h.createElement('iframe')` is missed and `React.createElement('iframe')` is still reported there.

### `react-jsx-key`

Port of eslint-plugin-react 7.37.5 react/jsx-key, default options. Reports an element (not a fragment) without `key` that is an array literal's element, or that a `.map(fn)` / `.from(x, fn)` callback returns: the arrow's body, a branch of its conditional body, the right side of its logical body, or a return statement directly in the callback body or in nested if/else branches. Never reported inside `React.Children.toArray(...)` / `Children.toArray(...)`.

### `react-jsx-no-comment-textnodes`

Port of eslint-plugin-react 7.37.5 react/jsx-no-comment-textnodes: JSX text with a line that starts (after whitespace) with `//` or `/*`.

### `react-jsx-no-constructed-context-values`

Port of eslint-plugin-react 7.37.5 react/jsx-no-constructed-context-values (it takes no options). Checks the first `value` attribute of a `<X.Provider>`, or of `<X>` where `X`'s first declaration is `const X = createContext(…)` or `React.createContext(…)`, when its expression builds a new identity: an object, array, function or class expression, `new`, a regex literal or a JSX element, also through the branches of `?:`, `&&`, `||` and `??`, the object of a member access without `?.`, the right side of an assignment, `as` and parentheses. A name passed as the value counts when it is declared in the exact scope the provider sits in (`let`/`const` in the same block, `var` in the same function, a function declaration there) and its initializer is such a construction, followed through further names declared in that scope; parameters, imports, class declarations and names from enclosing scopes never count, as upstream reads `scope.set` of the innermost scope only. The finding is reported where the value is built (the object literal, the initializer, the function declaration), as upstream reports it. Only providers inside a component as eslint-plugin-react detects one are reported: the nearest enclosing class extending `Component`/`PureComponent` (bare or `React.`), a `createReactClass` spec method, or an enclosing function that is a component by the plugin's naming and position rules (a capitalised function, variable, assignment target or object key whose function returns JSX, or JSX or null where upstream allows null; an anonymous returned or curried function; a `React.memo`/`React.forwardRef` argument, or `memo`/`forwardRef` imported from react, unless a `React.` wrapper's argument just returns a component declared in the file). Known limits: a `var` declared twice resolves to no declaration (upstream reads the last one), so such a value is missed; a lower-case tag such as `<ctx>` is looked up by name through enclosing scopes, seeing parameters, variable, import and function-declaration names but not class names; `componentWrapperFunctions` settings and `@extends` JSDoc on classes are not read.

### `react-jsx-no-duplicate-props`

Port of eslint-plugin-react 7.37.5 react/jsx-no-duplicate-props, case-sensitive. Namespaced attribute names and spreads are skipped.

### `react-jsx-no-leaked-render`

Port of eslint-plugin-react 7.37.5 react/jsx-no-leaked-render with the default strategies (ternary and coerce) and React 18 or later, so only `&&` is checked: a conditional is always accepted. Reports an `&&` that is the whole expression of a JSX container, in children or an attribute value (parentheses around it are transparent), at the start of the `&&`. Its left side passes when it is, through parentheses, a unary expression (`!x`, `!!x`, `typeof x`, `-x`), a binary operation other than `&&`, `||` and `??` (`x > 0`, `x in y`), a plain call (`f(x)`, `a.b()`, `a!()`), an `&&`, `||` or `??` all of whose operands are such expressions, the empty string, or a name whose declaration (the one the name resolves to lexically) initialises it with the literal `true` or `false`, however it is reassigned later. As in ESTree, an optional call (`a?.b()`, `a?.()`), a tagged template, `import()`, `await`, `new`, `x++`, `as`, `satisfies` and `!` assertions do not pass, and neither does a destructured, parameter or boolean-typed name without a literal initialiser. Known limits: upstream also accepts a name it finds declared in the first nested scope (and that scope's first nested scope) of a scope where the name is not declared, which the port, resolving names lexically, reports; and a file the grammar cannot parse is not checked, because the boolean-name test reads bindings.

### `react-jsx-no-script-url`

Port of eslint-plugin-react 7.37.5 react/jsx-no-script-url with its default options, where `<a href>` is the only link component (the legacy component list and `includeFromSettings` with `settings.linkComponents`, e.g. `<Link to>`, are not ported). Reports an `href` attribute, at the attribute, on a lower-case `<a>` element (opening or self-closing) whose value is a plain string literal starting with the `javascript:` protocol as React's URL sanitizer reads it: leading spaces and control characters allowed, tabs and line breaks allowed between the letters, ASCII letters in any case, with the attribute's HTML entities decoded first (`&#106;avascript:` counts). ### `react-no-access-state-in-setstate`

### `react-no-did-mount-set-state`
