# Mining notes: the sqlalchemy pack

What the pack's rules were chosen from, which candidates were dropped and why, and the order they were built in. The
corpus is the 20 repositories of `~/rerail-bench/python-arch/corpus` (MANIFEST.tsv); ten of them use SQLAlchemy,
SQLModel or Flask-SQLAlchemy: Netflix/dispatch, apache/superset, fastapi-users, full-stack-fastapi-template,
freqtrade, jupyterhub, langgenius/dify, mealie, open-webui, polarsource/polar. The probes below were run with
`python3` `ast` scripts over those ten (tests, migrations and Alembic versions left out) and with a library probe rule
(`corpus-run`); counts are probe counts, before any rule's own filtering.

Linters checked for overlap: the `python` pack (538 Ruff 0.16.9 and Bandit 1.9.4 ports; it has **no** S608/B608
port), Ruff's full list (no SQLAlchemy family), Bandit B608, pylint, mypy with SQLAlchemy's Mapped typing,
flake8-sqlalchemy(2), the Semgrep registry, and SQLAlchemy's own runtime warnings (LegacyAPIWarning, SAWarning).
Pack boundaries: Celery dispatch inside a SQLAlchemy transaction is the celery pack's; request data reaching SQL is
python-security's; `op.execute()` and migrations are alembic's; FastAPI dependency and route shapes are fastapi's.

## 3. The build list, ranked

1. `sqlalchemy-practice-bulk-write-skips-hooks` — data-safety, cross-file (hazard `orm.bulk-write-skips-hooks`).
2. `sqlalchemy-practice-session-reused-after-failed-commit` — availability: a swallowed flush error poisons the
   session for the rest of the request or batch (proposed hazard `tx.no-rollback-after-error`).
3. `sqlalchemy-practice-connect-without-commit` — data loss, silent (hazard `tx.writes-without-transaction`).
4. `sqlalchemy-practice-text-interpolation` — security (hazard `orm.raw-sql-interpolation`).
5. `sqlalchemy-practice-session-shared-across-tasks` — availability/data-safety (proposed hazard
   `orm.session-shared-concurrently`).
6. `sqlalchemy-practice-lazy-load-in-async` — availability: MissingGreenlet (proposed hazard `async.implicit-io`).
7. `sqlalchemy-practice-session-not-closed` — availability: pool exhaustion (proposed hazard
   `orm.session-not-closed`).
8. `sqlalchemy-practice-lazy-load-in-loop` — performance, cross-file (hazard `orm.query-in-loop`).
9. `sqlalchemy-practice-legacy-query-get` — maintainability (no hazard).

The rules' results (shipped or not, mode, corpus precision) are in the README; the independent review is
`REVIEW-sqlalchemy.md`.
