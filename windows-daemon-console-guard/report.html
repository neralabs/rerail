AConsole guard testsLow riskStart functions a stand-in test holds to the native spawn on every OS: 1 of 4 at main, 4 here.
Problem
If a later change starts the daemon with no console again, each Git it runs opens a window that takes focus, as with Rerail 0.1.3 (#507). At main the first to learn of it is a person at their desktop.
Who meets it
Every person who runs Rerail on Windows, once such a change lands. With 0.1.3 a Windows Terminal window opened every few seconds. Source: #507, which #503 closed.
What it does
runConsoleProbe writes a script and has the test start it through launchDetached. The script says whether CONOUT$ opens and starts two Gits, one without windowsHide and one with it. consoleHostsUnder counts conhost.exe under each in one read of the process table. Three tests start the daemon by startDaemon, startDaemonForPackage and relaunchDaemon on a stand-in Windows machine whose Node spawn throws.
Risk
Low. Nothing ships. A wrong probe costs contributors: a test that cannot fail gives false cover, and one that fails at random blocks CI.
Check
Can [0, 1] come from a process with no console? There the first Git gets a console host of its own: [1, 1] in 2 of 2 runs. Does childOf leave out only a host whose parent pid went to a later process? endProbe kills a probe 10 s after done, and the two Gits end when their input closes. The probe's own spawn is test code: the structure check covers src. In the test, launchProbe calls the real launchDetached.
BExit reason keptLow riskA second ask after the exit: throws at main, gives the same reason here.
Problem
On Windows, asking a launched process's exit reason again after it has exited throws. No person meets it: readyDaemon stops at the first reason. The probe's test asks again when it ends its probe.
Who meets it
No user today. The next caller that asks twice, and this pull request's probe test, whose endProbe asks until the probe is gone and once more. Source: a read of src at main, and the test runs.
What it does
On Windows launchDetached holds the first reason detachedExitReason gives in a local, exited, and returns it on every later ask (??=). While the process runs the reason is undefined, so each ask still reads the handle. The macOS and Linux branch already keeps the reason its exit event gave. Two doc comments say what the handle does.
Risk
Low. Two lines in the daemon launch. readyDaemon, the only caller in src, stops at the first reason, so no command's output changes.
Check
Does ??= keep only a reason, never the undefined of a running process? With a native binary built before the module kept a handle, detachedExitReason answers exited from the pid alone. Once kept, that answer stays if Windows gives the pid to another process, where main would answer undefined again. Is the kept answer the one you want there?

Six smaller gaps, six limits that stay
  • A new start path. A new way to start the daemon that calls none of the four start functions or launchDetached is not caught. A row of the owned-builtins check that lets only launchDetached pass detached: true would refuse it in src before any test. Not built here.
  • A fork's pull request. CI's unit jobs skip it, so the probe does not run there. A Windows job without the pack test data that runs npx vitest run test/runtime/daemon-control.test.ts would run it. Not built here.
  • The merge with #657. The start-path tests have not run on it. Whichever lands second keeps both import lists.
  • The other branch of startDaemonForPackage. It calls the same spawnDaemon as the tested branch. A test of it needs a stand-in machine with a healthy daemon from another package root. Main's test of that branch starts a real daemon and checks its pid and package root, not its start.
  • Repeated runs on Linux. This head did not run 20 times there: the four tests of the change that run on Linux use stand-ins and no timing.
  • Our own whole npm test did not run. CI ran it.

Limits that stay.

  • A child that a dependency starts detached, or with a new console, inside the daemon gets no console, or one with a window, whatever the daemon has. The probe covers a child started with neither.
  • A console that has a window: the probe reads whether a console exists. The Rust test starts_the_daemon_with_a_hidden_console_not_without_one holds the flag.
  • Windows from processes Rerail does not start: a coding agent's hook process, the CLI in a terminal, Git hooks, credential helpers. And spawnShown, which shows one by design.
  • Each Git the helper starts still gets a hidden console host of its own. The control Git measures it (1), and it stays as main designs it.
  • A Windows whose console host is not conhost.exe: every count reads 0, and the control Git fails the test.
  • Main's test "goes through the native spawn on Windows, whose hidden console the daemon's Git and npm share, never Node's detached spawn" keeps its name. It checks the arguments handed to the native spawn, not the sharing.
