## Abstract

Phase B is a **residency and lifetime change**, not a replacement matcher. The roadmap replaces the workspace's resident per-file Tree-sitter trees with compact structural tapes and bounded postings; evaluation materializes one candidate file's tree, runs the existing ast-grep-based matcher, emits its results, and drops the tree. The deck also removes resident candidates/witnesses/violations in favor of recomputation and changed-file deltas. Source ownership, compact dispatch metadata, failure state, and aggregate bookkeeping still need explicit designs; “tapes replace trees” is not permission to discard observable results. Phase C, separately, lowers code rules to an IR and matches directly on tapes with **no Tree-sitter tree or native ast-grep in the query path**. Joins, absence, grouping/counts and cross-file semantics belong to later phases. [Deck pp. 34–39][deck]

The immediate task is **read-only orientation and a concrete Phase B design/decision outline, then wait for Jeff**. Read the sources below, identify feasibility gaps, publish an implementation plan before broad production edits, and do not presume authorization for a full rewrite, benchmark run, or numerical acceptance gate. In particular, the deck's “decode tape → rebuild Tree” is a proposed boundary, not proof that the installed Tree-sitter API can construct a native tree from these records. The first design question is how to satisfy that boundary safely without quietly implementing Phase C.

### What the spike actually proves, and what it does not

The v2 codec stores **all concrete syntax nodes**, including anonymous punctuation, in preorder. Its `rec` is six bytes per node: little-endian packed kind/field, parent delta, subtree size. Separate delta/length varints supply source byte spans; checkpoints bound span lookup; `0xFFFF` parent/size sentinels require overflow entries. Source text remains separate and spans are views into it. `pack_kf` rejects kinds outside ten bits and fields outside six; three-byte checkpoint fields are additional bounds to account for. These are reference-format constraints, not license to truncate large files or unsupported grammars. [S011/S040/S047][spike-design]; [`tape_v2.py:44–173`][spike-code]

Read current code over stale prose: S047 still says checkpoint stride 128 and names `encode_kf`; S008 and `tape_v2.py` use **16**, and the function is `pack_kf`. Earlier S012 prose says named-only; S011/S040 reverse that decision and the encoder visits every child. Resolve such discrepancies explicitly rather than copying both conventions.

Crucially, `tape_v2.decode()` returns the spike's Python `Tape` structure-of-arrays, **not** a native `tree_sitter::Tree`. S044's “rebuilds the tree” refers to that decoded structure. Rerail currently pins Tree-sitter **0.27.0** and ast-grep **0.45.3** in `rerail/native/Cargo.toml`; the [Tree API](https://docs.rs/tree-sitter/0.27.0/tree_sitter/struct.Tree.html) exposes parsing-related tree operations and raw-pointer ownership conversion, not a documented constructor from arbitrary node records. `from_raw` is not tape deserialization. Establish feasibility against the installed implementation before proposing a codec as a solved native reconstruction path. A reparse of retained source, a decoded representation/adaptor, and a new matcher are not interchangeable options: explain which preserves the intended B boundary and where approval would be needed to change it.

The spike's main design is SQL-centric (S002/S010); Rerail's roadmap explicitly chooses a stand-alone local path. Do not import a database, SQL execution model, or the spike's later matcher as incidental Phase B infrastructure.

## Design obligations and acceptance questions

### Residency and lifecycle

- Specify a lifetime/ownership table for source, tape, grammar tables, postings, decoded scratch, parser scratch, tree, node handles, previous revision, witnesses, violations, failures and synthetic/global state. State which are resident, per-file transient, response-owned or shared.
- Meet the **one-file transient tree** intention on initial ingestion as well as evaluation, edit, replacement, deletion, cancellation, parse failure and close. Do not retain an old native tree while claiming only one tree is live; incremental parsing overlaps edited old and new trees, and a document that wraps a native tree clones its handle. Distinguish handles, shared backing storage and distinct tree versions when accounting.
- Decide whether an edit reparses current source and fully reevaluates the file, or has another proved bounded strategy. Do not reuse witnesses using text-only edit spans when syntactic context may have changed; fully invalidating can be semantically safe but its CPU/budget effect must be measured later.
