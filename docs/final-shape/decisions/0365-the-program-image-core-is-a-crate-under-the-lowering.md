# 0365: The program image's core is a crate under the lowering

**Status:** building (the user's choice, 2026-11-17).

## Intro

Decision 0281's step 7b has the lowering write each clause's rules through the program image's `Builder` as the tape
walk reads them, so a module's program is a version from the start, not a `front::Program` encoded afterwards. The
lowering (`rr::lower`) is compiled in `rerail-rr`; the image (`Version`, `Builder`) in `rerail-logic`, which depends
on `rerail-rr`. The lowering cannot name the builder.

Asked how the lowering should reach it (move the image's core down, a rule sink trait in `rerail-rr`, or the lowering
moved up), the user chose: "move it down into a new crate under rerail-rr".

## Decision

1. **A crate `rerail-program-image` between `rerail-rr-syntax` and `rerail-rr`** holds the image's core: the module
   root (`Image`, the writer, `encode`, `decode`, `about_of`), `about`, `build`, `csr`, `encoder`, `extents`,
   `grouped`, `handles`, `show`, `strings`, `tree`, `version`, and `program_facts`, which the about rows are. It reads
   only the AST (`front::ast`, `front::name`) and the profiler. `rerail-rr` depends on it, so the lowering writes
   versions.
2. **The pass manager, the passes and the analyses stay in `rerail-logic`** (`manager`, `passes`, `analyses`, the
   image's tests): they read the planner. `rerail-logic`'s `program_image` is the core's, globbed, with them added,
   as the crate split mounts a module two crates share (`tools/cratify/mounts.py`).
3. **What tied the core upward is cut, not moved:**
   - a version's analyses: `Version` keeps a type-erased slot, which the manager fills with its `Store` on first use
     (`manager::analyses`), in place of a `Store` field of the manager's type;
   - `Version::part` and `Version::part_rules`, which run passes: a trait beside the passes (`passes::Parts`);
   - `front::operator`, which `program_facts` reads: in `front::ast`, beside the AST, with the parser's punctuation;
   - `program_facts`' tests that read text through `rr::parse`: moved to the image's tests, which stay above.
4. **The files stay where they are**: the new crate mounts them in place (the crate split's `proposals/crate-split/in-place-plan.md`), its lib.rs
   generated by `mounts.py` from `crate-map.tsv`.

## Consequences

- An edit to the image's core recompiles `rerail-rr` and everything above it; an edit to the manager or a pass does
  not.
- The blocks port (0281, last) replaces this crate's insides; its `Version` interface is the one the lowering writes
  through.
