# M2 and M7: fused executor speed and the budget cases

Code and outputs: `../experiments/m2m7/`.

**Verdicts**
- **M2: PASS.** Fusing transaction-patterns (TP) and async-sync-delegation (ASD) gives exactly the native matcher's finding set at **0.26 ns per program-node** with all 58 TP clauses, and **0.40 ns per program-node** with default options. ASD alone sits just under the target at 0.86–0.93 ns.
- **M7: PASS.** sync-async-signatures (SAS) finishes `generated_facades.py` in 20 ms and the 1,000-function file in 3.6 ms, with no budget or depth limit hit. Native fails its budget on both, and on anything from about 100 function pairs up.
- **N1562 packed CPU interpreter/JIT:** none of the three rules lowers to it.

Timings are thread CPU time, minimum of 5 runs (3 for M7), single core, parse time excluded. The machine was shared at load averages of 38–70 on 18 cores, which inflated wall time about 3×.

All files are under `../experiments/m2m7/`.

**How I handled fact keys.** The fusion-model harness treats compare, count, layout, parametric utils, `$option` templates and `pattern $X` as always true, and it uses the stock tree-sitter-python grammar. That makes it a superset: 4,402 findings on the 36 default queries, against 0 real ones. My executor implements all of those keys exactly, including transform/replace, parametric utils with parameter aliasing, layout `before`, count, value/str decoding, filePath, `$option` cases and templates, `when.option`, `file.path` regex/notRegex, and `syntax: valid`. It uses native's patched grammar (PEP 696 defaults, lone CR). The stock grammar flags 46 corpus files as having errors and lost 67 TP keys in 14 of them; the patched grammar flags none.

## M2 step 2: the executor

The executor is a Rust crate in `exec/`: `src/main.rs`, binary `exec/target/release/m2exec`. Its features:
- Shared sub-rules are hash-consed into a DAG. ASD's 111,549 rule expansions compile to 1,629 ops; TP all-clauses compiles to 317.
- Nested `all` is flattened, and `any` branches share common prefixes with their order kept.
- Programs share a root prefix trie, but only on conjuncts that read no captures.
- Conjuncts that read no captures are reordered by cost/(1−selectivity), calibrated on every 10th file. Calibration takes about 0.02 s.
- Epoch-stamped memo columns, plus memoised bindings and memoised utility calls.
- A keyed set stage that buckets `has stopBy: end` candidates by name text.
- Adaptive masks for range relations that read no captures.
- Regex results interned per distinct leaf text across the corpus.
- Dispatch through a kind-postings index, and a fast path for leaf nodes.

**Parity: identical finding sets wherever native completes.**
- TP all-clauses: 1,244 = 1,244.
- TP default: 0 = 0.
- ASD: 0 = 0.
- Both rules fused in one run: 1,244 = 1,244.
- Fixtures: native = oracle = mine on 97/97 events (53 keys), in plain, memo and mask modes, with and without the trie and reordering.

## M2 step 3: speed

In the tables, "pn" is a program-node: the number of programs times the nodes in the rule's scope. "Plain" turns off memo columns, bind and call memo, keyed lookup and masks; factoring, the trie and reordering still apply.

**Fused, TP all-clauses + ASD:** 71 programs, 835.8M program-nodes (594.0M after file-path filters).

| Config | CPU | ns/pn | Evaluations | ns/eval |
|---|---|---|---|---|
| No fusion, plain | 2.467 s | 2.95 | 363M | 6.8 |
| No fusion, memo | 0.469 s | 0.56 | | |
| Factoring, memo | 0.316 s | 0.38 | | |
| Trie, plain | 0.236 s | 0.28 | 19M | |
| Trie + inner reorder + index dispatch, plain | **0.214 s** | **0.255** | 15.9M | 13.4 |
| All reordering + index dispatch, plain | 0.280 s | | | |

**Fused, TP default + ASD:** 36 programs, 423.9M program-nodes.
- No fusion: plain 1.263 s (2.98 ns/pn); memo 0.443 s (1.04).
- Trie, plain: 0.222 s (0.52).
- Trie + inner reorder + index: 0.194 s (0.46).
- All reordering + index: **0.171 s (0.40 ns/pn)**, 9M evaluations at 17.2 ns.

**Per rule:** best config was full reorder + trie + index dispatch, plain mode (from the `REORDER`/`TRIE` matrix).

| Rule | Program-nodes | No fusion | Best | Best ns/eval |
|---|---|---|---|---|
| ASD | 153.3M | 1.99 ns/pn | **0.86 ns/pn** (0.131 s) | 15.1 |
| TP default | 270.6M | 3.02 ns/pn | **0.11 ns/pn** (0.030 s) | 23.1 |
| TP all clauses | 682M | 2.75 ns/pn | **0.11 ns/pn** (trie only, 0.073 s) | 8.1 |

ASD lands between 0.86 and 1.02 ns/pn across runs. It is the borderline component: 13 programs with deep recursive utilities, and very little to share across programs.

**Reference: the fusion-model harness** on the same 36 default queries (wall time, superset semantics): separate 3.19 s (172M steps), memo 0.40 s, mask 1.07 s.

**Gap to 1 ns and what dominates.** We are 2.5–4× under the 1 ns target on the fused pair, with headroom only about 1.1× on ASD. Per-evaluation cost is still **13–17 ns**, against the spec's 3–5 ns. The pass comes entirely from doing 20–40× fewer evaluations (trie, reordering, factoring), not from cheap evaluations.

Profile of the best config:

| Component | Share |
|---|---|
| Interpretive evaluator (`eval_raw` / `eval_in` / `hit`) | about 74% |
| Regex, mostly module-text sourceGate scans over 75–159 MB | about 6% |
| `trie_walk` | about 5% |
| Variable references and transforms | about 4% |
| malloc | about 3% |

Memo columns did not pay once regex results were interned: memo mode runs 10–15% slower than plain on ASD. Masks were almost never promoted (2 builds).

**Caveats**
- The reordering is calibrated on a sample of the same corpus it is measured on.
- The call-memo key is a 64-bit hash.
- Two latent bugs were found and fixed along the way; both are lessons for a production fused executor:
  - The transform cache was keyed without the program, so different clauses' transforms for the same variable name collided. Reordering exposed it as 4 fixture false positives.
  - The bind-memo condition ignored variables under `not`, `count` and `nth`.
- A single-level trie that shares only the kind prefix fails once the rules are combined (326M evaluations). It has to be a recursive prefix trie.

## M7: sync-async-signatures through the mask-lowering path

Runs used memo mode with the keyed set stage and call memo. Outputs are in `out_m7_*.json`; synthetic inputs are in `syn/`.

| Input | Without keyed (`KEYED=0`) | With keyed | Findings | Peak RSS | Native |
|---|---|---|---|---|---|
| `generated_facades.py` (206,043 nodes, 906 functions) | 0.141 s | **0.020 s** (906 entries indexed) | 0 | about 52 MB | budget-exceeded after 1.9 s CPU |
| s1: 1,000 sync `op_i(txn: WriteTransaction)` + 1,000 `op_i_async(conn: SyncDatabaseConnection)`, 51k nodes | 0.451 s (20.7M evaluations) | **0.0036 s** (201k evaluations) | 1,000 | 21–23 MB | budget-exceeded ("`matches` and `count` exceeded their work budget") after 651 ms CPU, 220 MB RSS |
| s2: 1,000 sync + 10 async | 0.078 s | 0.001 s | 10 | | budget-exceeded |
| s3: 1,000 same-name pairs (adversarial: everything in one bucket) | 0.160 s | 0.061 s | 1 | | budget-exceeded |

- No budget or depth cut was hit in any run (`util_depth_cut` = 0).
- **Scaled synthetics:** findings match native at 10, 30 and 60 pairs (variants p, q and r). Native exceeds its budget from 100 pairs up (p100, p200, p400), while mine completes.
- **Without keyed lookup the cost grows quadratically** (p100 5 ms, p200 16 ms, p400 71 ms). The keyed stage turns that join into a lookup by name.

## N1562 packed CPU IR

This comes from reading the ner-1562 worktree (no build was run). None of TP, ASD or SAS lowers:
- The `syntax` and `filePath` keys are missing (`compile/mod.rs:713-726`, `ast_rule.rs:26-50`).
- Lowering is all-or-nothing, with no per-clause fallback (`query/relational.rs:165`; `lower_matcher` at `:1372-1773`).
- Even with those keys ported, recursive utilities under negation are rejected (`:2536`, `:2149`, `:2161-2166`). That affects TP's `annotation-has-connection`, SAS's `annotation-interesting`, and probably ASD's `static-return`.
- There is no standalone packed benchmark, and the docs make no ns-per-node claims.
