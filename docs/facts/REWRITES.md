# Rewrite registry (INVARIANTS I4)

Owner: S1. The logical side lives in `rerail-facts`; S2 implements the physical side.

Every rewrite takes the algebra (`ir::Rel`, or a resolved pattern query before it becomes a leaf), never SQL text or a name. A row lands here with:

- its side conditions, checked in code;
- its justification;
- its differential test;
- its mutant.

Mutants are `crate::mutant::on(n)` at the rewrite's site, behind the `mutants` feature. Run one with `FACTS_MUTANT=<n> cargo test -p rerail-facts --features mutants --lib`. The gate parses the `mutant` column, cell format `<n> <kind>`.

Numbers:

- 1–3: S2's interim A3 views;
- 4–6: S3's delta generator;
- 7: classifier;
- 8: planner audit (inner scans);
- 9: S3's runtime tie detection (windows and `LIMIT` not provably total; a tie between distinct rows is a runtime refusal);
- 10: order proofs (`classify::KeyEnv::total`: every order taken as proven total; killed by `classify::tests::order_marks_proven_and_checked`);
- 11 upward: rewrites (R6–R11: 16–21).

## Which rewrites retire `subst.rs` (S2's physical side)

|---|---|
| dump groups (`syntax_N` inputs unioned by `syntax_rows_k`) | pattern front end (`front::pattern`, matcher inputs as algebra over `node`) + R7 (one pass over `node` for the arms) + R6 (the union stage read once by `nodes`) + R8 (unread capture columns not computed) |
