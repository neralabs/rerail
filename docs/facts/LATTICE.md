# Lattice facts: design invariants (scratchpad)

Status: **proposal under exploration; amended 2026-10-29 after E0 and E1** (`reports/lattice-e0-census.md`, `reports/lattice-e1-cpu.md`). Not binding; `INVARIANTS.md` I1–I10 still govern everything outside declared lattice facts. Origin: Jeremy's claim that replacing the static lattice with declared, memoised recursion "buys out a lot of complexity", the user's direction that the fixpoints run as a parallel matrix across rules, and two constraints from the user: execution must have a **very regular shape** to be fast, and on Apple silicon the data **should not move** (unified memory). Numbers are copied from a cited run or marked `[unverified]`.

## Thesis

Rules are Datalog over declared facts. Recursion is a declared monotone fixpoint over a lattice from a closed catalogue, or, for trees, no fixpoint at all (an interval probe); the engine owns evaluation, parallelism and maintenance. Every fixpoint round is the same regular operation: a sparse matrix (an edge relation in compressed layout, itself a maintained fact) times a dense frontier, over the lattice's semiring, on columns that every worker reads in place. Speed comes first from that shape on one core, then from running many independent fixpoints (contents, worktrees) side by side; splitting one fixpoint's rounds across cores is the exception.

```
rule  → reads declared facts (DECLARED-FACTS.md)
fact  → non-recursive: plan as today (I5, I7)
      → recursive: { seeds, edges, lattice } → stratum
stratum → rounds: frontier' = (edges ⊗ frontier) ⊕ values, until no value changes
        → parallel over contents | over worktrees | over independent facts; within a round only above a measured size
edit  → insert: continue the rounds from the new seeds/edges
      → delete: the lattice's own maintenance algorithm, over the affected frontier
```

## Why this could remove complexity (what is claimed)

A monotone fixpoint over a lattice reaches one least fixpoint whatever the evaluation order, the partition and the thread count (joins are commutative, associative, idempotent). If every recursion is of that kind, the engine needs no ordering between rules inside a stratum, no per-rule delta rules, no locks on derived state, and no order-dependent refusals inside the recursion. The cost moves to a small, fixed set of engine-owned algorithms: one evaluator, one maintenance algorithm per lattice.

## Invariants

| Id | Invariant | Forbids | Enforced by |
|---|---|---|---|
| L1 | **Recursion is declared, not written.** A recursive relation is a `facts` entry `{ seeds, edges, lattice }`: seeds and edges are non-recursive plans over facts; the lattice names how a value is kept and combined. Rules read the fact by name. A legacy `WITH RECURSIVE` runs on the existing `Fix` (I1 semantics) unless a registered rewrite proves it equal to a declared lattice fact (I4). | Recursion spelled out in rule text for new rules; the engine recognising a CTE's shape and swapping in a lattice without a registered, side-conditioned rewrite | compiler: `facts` with `lattice` is the only recursive construct new packs may use; rewrite registry |
| L2 | **The lattice catalogue is closed and engine-owned.** Each entry states: carrier, join, bottom, the ascending-chain bound (finite height, or bounded by input size), the semiring used by a round, its maintenance algorithm, a differential test against the reference and a mutant. Catalogue: `set` (∨, ∧ over booleans), `min_level` (min, + over ℕ ∪ {∞}), `best_witness(key)` with key = (integer weight sum, lexicographic sequence), extension-monotone (a least key extends a least key), proven total by I2; its per-round ranking cost is declared, and a stage's final pick may add tie-breaks that propagation drops. Integer weights only, so results do not depend on reduction order. Unique-derivation folds (string path-folds, string unfolds, ordered folds: one derivation per row, no join) are not lattices and are expressed by non-recursive ordered operators (ancestor aggregate, split table function, ordered fold). | User-defined joins; float carriers; a lattice whose height the engine cannot bound; "best" without a total key; folds dressed as lattices | catalogue in code; per-entry test + mutant; compile-time refusal of anything else |
| L3 | **Monotone inside a stratum, ordered between strata.** A step reads its own stratum only through monotone operators (join, union, projection, the lattice's ⊗). Negation, aggregation, windows and `LIMIT` read only completed strata. | Negation or aggregation over the relation being computed; non-stratifiable programs | dependency analysis in the compiler; refusal by construct (I9) |
| L4 | **Results are independent of schedule.** The result of a stratum is a function of its inputs alone: identical across thread counts, partitions, backends (CPU, GPU) and round orders. Thread count, partition and backend are never part of a memo key. | Results or tie-breaks that depend on which worker got there first; per-thread memo keys | gate check: every lattice fact evaluated at 1 and N threads and on each backend, bit-identical |
| L5 | **Regular execution shape.** A round is one bulk operation: edges in CSR (u32 offsets, u32 targets, both sorted), the frontier as a bitset (plus a sorted u32 list while sparse), lattice values in a dense array indexed by a u32 id, the step as sparse-matrix × frontier over the semiring. No allocation per row, no hash map and no pointer chasing in the inner loop, no per-node dynamic dispatch. **Id assignment is part of the layout:** ids stay key-local (hashing ids balances work but doubled one-core time in E1), and high-degree rows get their own work units at build time. The edge relation is a maintained fact (L9), never rebuilt per evaluation. | Per-key memo re-runs as the evaluator of a fixpoint (they may stay as bookkeeping around it); `HashMap` probes per derivation; `Vec` per node; work stealing over tasks of unbounded size; a CSR rebuilt cold per edit | plan audit (no hash or alloc operator inside a lattice round); counts per round (L8); review |
| L6 | **Data does not move.** Facts live once, in their execution layout, in memory every worker reads in place: columns mapped from the content store, shared read-only by all CPU threads and, when used, by the GPU through shared buffers (Apple unified memory; page-aligned no-copy buffers). Across contents or worktrees, each worker owns its fixpoint's value array outright. Within a round, the join is an atomic `fetch_min`/`fetch_or` into the one shared value array; partitioned owner writes are not used (buffers grow with threads, E1). No serialisation between stages, no per-worker or per-device copy of a shared fact, no host↔device transfer. | Copying facts into a worker or device; converting columns between stages; a second resident copy of a shared relation | memory accounting counts mapped pages once and reports private bytes per worker; a copy-count counter in the physical counts (`LOOP.md`) must read 0 for shared facts (E1: 0 in every run) |
| L7 | **Parallelism is the engine's, across independent fixpoints first:** the default work unit is a whole fixpoint (one content, one worktree, one independent fact of a stratum) per worker; on the GPU, many fixpoints in lockstep rounds (a frontier matrix). A single round is split across workers only when its edge count exceeds a threshold set from counts (≈ 300K edges on this machine, deterministic so L4 holds). Never across rules that share a fused pass over one content. | Rule-level threads over the same content's facts; splitting small rounds; parallelism that changes a result (L4) | scheduler is the only component that creates work units; fused passes are single units; the threshold is a count, recorded in `EXPLAIN` |
| L8 | **Cost is visible per round.** Each lattice fact reports rounds, frontier width per round, derivations, edges scanned, and bytes moved, as algebraic counts (`LOOP.md`). Rounds bound the critical path; frontier width bounds the parallelism available in a round. A fact whose rounds exceed its declared bound, or whose work exceeds O(edges × height), is a named refusal. | Wall-clock-only claims of parallel speedup; unbounded rounds | `EXPLAIN ANALYZE` counts; the count-regression check |
| L9 | **Maintenance is per lattice, not per rule.** Insert: continue the rounds from the new seeds and edges (monotone, so exact). Delete: the lattice's algorithm over the affected frontier, still in the L5 shape: `set` by support counts or over-delete-and-rederive restricted to the affected ids; `min_level` by levelled re-check (a node keeps its value while a predecessor at level − 1 survives; Y2's reached set); `best_witness` by re-check of the nodes whose witness was removed. Incremental ≡ from scratch on the replay. | Hand-written delta rules per fact; recomputing a whole stratum on an edit when the lattice has an algorithm | replay check after every event (as Y2/Y3); per-lattice mutants |
| L10 | **Layered state.** A lattice fact's values and its edge relation follow the membership layering: base, cluster overlay, worktree delta (Y1); E1's layered CSR (base + a bit and a rank per id + delta rows) reads at no visible cost. Per-worktree state is proportional to divergence; a new worktree costs nothing. Divergence is measured after rule shape: per-method dispatch states fan a small edit out to ~12.6K replaced rows per worktree; dispatch keyed by class is the rule-side fix. | A full copy of the values per worktree | memory per worktree against divergence, as B4 |
| L11 | **Tree closures have no rounds.** A closure over a forest (FD child → parent) is an interval probe over preorder ids (`(id, subtree_end]`), R9 extended to the rules' derived `edges` stages; nearest/farthest-ancestor overrides are interval or ancestor-witness lookups. This is the largest recursive cost in the rules (E0) and it is removed, not parallelised. | A fixpoint, lattice or not, over a declared forest | registered rewrite with the forest FD as side condition; count check that tree-closure stages report 0 rounds |

## How this amends I1–I10

- **I1** (SQLite semantics): unchanged for legacy recursion. A declared lattice fact has lattice semantics, not `WITH RECURSIVE`'s; it is a new construct (I1's last bullet: new constructs enter through the IR), so SQLite is not its oracle. Its oracle is the reference evaluator's naive fixpoint.
- **I5**: adds one physical operator, the semiring round over CSR (`spikes/facts-b/src/lattice/round.rs`), and extends R9 to derived tree `edges` stages (L11); the existing `Op::Fixpoint { seminaive }` (`spikes/facts-a/src/physplan.rs`) remains for legacy recursion.
- **I8**: for lattice facts, incrementality is per lattice (L9), not generated per plan; the edge relation is maintained as a fact. This resolves the I8 vs Y3 inconsistency for recursive relations; non-recursive membership plans keep I8 as written.
- **I9**: a user lattice is refused by name (L2); E0 found no rule that needs one.

## Experiments

- **E0 census (no engine change).** For each of the 68 recursive CTEs: what it recurses over (syntax tree, reference graph, call graph, strings), set or bag, what value it carries, which catalogue lattice it is, whether it is monotone, and whether it is per-content or membership. From the existing counts on batch 6: derivations, rounds and frontier width per round, and the recursive stages' share of the rule's work. Answers H1–H3.
- **E1 regular fixpoint on the CPU.** A semiring-round operator (`set`, `min_level`) over CSR on mapped columns; dead-code reachability over Y1's reference graph (cold, oracle tree) as the first input, then the heaviest recursive stage E0 finds. Exact against Y2's reached set and the reference; counts and wall at 1–18 threads; private bytes per worker. Answers H4, H5.
- **E2 Metal backend.** The `par` round (atomic join) as a compute kernel over shared no-copy buffers, with the fleet as the unit: 41 worktrees' frontiers in lockstep rounds, tail rounds (< 10K edges) on the CPU; bit-identical to E1. Answers H6.
- **E3 maintenance.** L9's `min_level` and `set` deletion and the CSR's row maintenance in the L5 shape on the 1,111-event replay. Answers H7.
- **E4 tree closures (L11).** R9 extended to the rules' derived `edges` stages with the forest FD as side condition; measured on facts-a against the current tree closures (state-flow-1 `descendants` is the heaviest recursive stage). Not in the original plan; E0 says it is the largest recursive lever.
