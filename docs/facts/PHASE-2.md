## Deliverables

1. **Rule IR.** Relational algebra over typed columns with SQLite affinity semantics: select, project, join (equality and general predicates), antijoin, group-by with count and ordered `group_concat`, window `row_number()` with a total order, correlated `EXISTS`/`IN`, union, recursive fixpoint with set semantics. Two front ends: the pattern DSL (existing rules; matcher queries become IR leaf relations over facts) and Jeremy's SQL stages (Spike A's parser). Every construct the 60 rules use is either in the IR or refused with `Unsupported` naming the construct.
2. **Classifier.** `partitionBy: file` and repository clauses are declared; the compiler verifies the declaration. A per-file plan may read only: the facts of one content, rule-private derived facts of that content, and constants. Any reference to `calls`, `reference_edges`, name closure, other files' facts or exported relations is a compile error in a per-file plan. A repository plan reads only exported facts. Enforcement is by construction: the per-file backend receives a `FileFacts` handle with no path to anything else.
3. **Per-file backend.** Spike A's executor plus: A3's substitution views as compiler rewrites (stage shape → fact view), per-rule memoization keys `(content hash, schema version, rule digest)` with the content store's completion words, streaming evaluation with nothing accumulated across files, and cross-clause sharing of identical sub-plans if A3's residue says it is needed.
4. **Cross-file backend.** Compilation of repository plans to the tagged dataflow: generated delta rules for join, antijoin, count and group-by; demand-driven recursion materialized per worktree only when its delta touches the recursive inputs; per-path base and cluster bases; exported facts resident only for member hashes; outputs as epoch-stamped finding deltas. The exported relations are whatever the repository plans' leaves need, projected and made distinct in the per-file stage; nothing occurrence-level is exported when a symbol-level relation suffices.
5. **Reference evaluator and gate.** A naive from-scratch evaluation of the same IR over a worktree's facts. The gate compares: compiled per-file plans against the oracle on the recordings and the repository; the dataflow against the reference on Spike B's edit replay, with the real repository plans; seeded mutants in the delta rules and the substitution views, each of which must be caught. The gate is one command, like `rerail-sql-gate`.
6. **Fact schema v1.** Syntactic core; Python-derived relations the census needs (`function`, `class`, `parameter`, `call`, `argument`, `attribute`, `assignment`, `decorator`, `import`, decoded strings, f-string parts, lines); exported relations; schema version in the fact-file header; a decision on storing anonymous nodes versus re-deriving them, and on compression. The `string_type_definition` fact is scheduled here or the rule's scope is narrowed with Jeremy; one or the other, decided in the first week.
7. **Census and plan audit** over all 60 rules: compiles, classification, unsupported constructs, fact volume per exported relation, and the sharing census (which stage texts recur across clauses).

## Gates

| Id | Gate | Target |
|---|---|---|
| G2.1 | All 60 rules compile and classify; a seeded cross-file leak in a per-file rule is rejected at compile time | 60/60; the leak test fails to compile |
| G2.2 | Batch-6 parity through the compiled per-file path | recordings and repository exact for the 9 rules; the 10th exact once `string_type_definition` lands, or its narrowed scope agreed with Jeremy |
| G2.3 | Batch-6 repository CPU through the compiled path, parity unchanged, **with no shape-recognized substitution left** (`subst.rs` and the `FACTS_A3_*` switches deleted; generic rewrites only) | ≤ 90 s CPU (≤ 23% of native's 393 s; A3 measured 152.6 s with substitutions), i.e. ≤ 10 ms per file p50 for the 10 heaviest rules; stretch ≤ 40 s. Levers with A3's sizes: Python-derived relations as per-content views shared by semijoin under subtree closure (34.9 s of byte-identical stage text today), columnar operators instead of materialised rows (15.1 s in views plus the `n.*` copies inside the 82.4 s of SQL), memoized per-node predicates for the selections (28.5 s), per-process regex cache and no per-statement drops (~8% of samples) |
| G2.4 | Repository plans on the dataflow | the 8 repository clauses and the `calls` rules: oracle parity on `2b1504adc`; incremental ≡ from-scratch on the 1,000-edit replay; 40 worktrees resident ≤ 250 MB with the real plans (B3's 195 MB plus their state) |
| G2.5 | Memory | RSS at the end of the per-file phase ≤ 300 MB for the 9,010-file run with 4 workers (A3: 52 MB); per-worker peak ≤ 256 MB on the largest corpus file (764 KB, 148,502 nodes; A3: ~640–830 MB per worker from `descendants` and `n.*` copies O(nodes × depth)); compiled rules one immutable shared object per process, ≤ 32 MB for batch 6 (S2 measured ~320 MB per worker today). `descendants` is an interval probe on facts, never a materialised relation |
| G2.6 | Gate strength | every seeded mutant caught; the gate runs in ≤ 10 min |

Kill criteria:
- A construct a repository plan needs cannot be expressed incrementally (for example `row_number()` over a per-worktree partition with ties): refuse it, record it, narrow the rule with Jeremy. No approximation.
- G2.3 missed after substitution: cross-clause sharing becomes a compiler pass; if still missed, the rule shape (per-clause tree rebuilding) is raised with Jeremy as a rule-authoring change, since the engine cannot remove work the rule insists on.
- G2.4 memory > 500 MB: hierarchical bases per Spike B § 6; then eviction of idle worktrees.

## Slices (one executor each; parallel where no arrow)

- **S1 IR + front ends + classifier + census + rewrite registry + EXPLAIN.** Crate `facts/` (`rerail-facts`). Delivers the IR types with fact-relation metadata (keys, FDs, preorder order and interval property, cardinality bounds); the SQL and pattern front ends (no SQL text past `parse`; `Plan` holds only relations and expressions); classification by dependency analysis of leaves with `partitionBy` checked against the inferred class; the leak test; the 60-rule census; `docs/facts/REWRITES.md` with each rewrite's pattern, side conditions, justification, test and mutant column; `EXPLAIN` (printer over the physical plan, stable text) and the inner-scan plan audit; compiled plans immutable and shareable across workers. Interface: `compile(rule) -> Result<Program, Unsupported>` with `Program { per_file: Vec<Plan>, repository: Vec<Plan>, exported: Vec<ExportedRelation> }`.
- **S2 per-file backend.** From Spike A's executor; A3's `subst.rs` is a benchmark oracle only and is deleted when the generic path holds or beats its numbers. Delivers, in this order: engine hygiene (per-process regex cache, no per-statement drops); the columnar physical layer (column stores, fact-backed relations whose values borrow from fact columns and the source slice, frames binding `(relation, row)`; operators per I5); matcher inputs as node-id relations over `node`/`child`/`field` (the physical side of S1's leaf relations); the physical side of the generic rewrites (view inlining, union-of-selections, projection pruning, tree-reachability-to-interval with side conditions checked per file and exact fallback, selection sharing under subtree closure); compiled plans shared immutably across workers; memo keys `(content hash, schema version, plan digest)` and completion words; streaming with nothing accumulated across files. Every step re-runs the differential (rewritten vs unrewritten plan over the corpus) and the parity comparators.
- **S3 cross-file backend.** From Spike B's dataflow. Delivers the generic delta-plan generator over `rerail_facts::ir` (bilinear join expansion over the tag tree, count-based distinct/semijoin/antijoin and group aggregates, semi-naive fixpoint demand-driven from targets, stratified negation), the membership model (per-path base, cluster bases, worktree deltas), resident-fact eviction by membership, and refusals named per repository clause (windows with ties, `LIMIT` with a partial order, `argmin` on a tie, bag-recursive path enumeration). Spike B's R1–R3 and any interim plans are the generator's test vectors, written as logical algebra, never as delta code; no hand-compiled plan ships.
- **S4 fact schema v1 + extractor + store format.** Serves S2 and S3. Delivers `SCHEMA.md` v1: the syntactic core with its declared structure (I2); the exported relations S3 names; the Python-derived relations (`parameters`, `calls`, `assignments`, `import_identifiers`, `methods`, `decorators`, `return_kinds`, `contexts`, `special_attributes`, `attributes`, `functions`, `classes`) **as SQL views over the core**, compiled and memoized per content by the same compiler, each checked over the whole corpus against the policies' shared stage text over gate-true nodes; the extractor minimal (core plus parser facts: decoded strings, f-string parts, `string_type_definition(host_id)` from native's existing Ruff 0.16.9 classifier, per content); versioned fact files with the measured anonymous-node and compression decisions (8.3× source today).
- **S5 gate harness.** `just facts-gate [--mutants]` (committed `f208cfd0e`): Spike A's replay and repository parity, the rewritten-vs-unrewritten differential on a deterministic subset, Spike B's exactness replay, the classifier leak test, `explain-stable` (plan text identical across runs and files), and mutants read from `REWRITES.md` (one per rewrite; the gate fails while a rewrite lacks one or its mutant survives) plus fixed mutants for the delta generator, the classifier and the planner audit. `--engine facts` in Jeremy's `replay.ts`/`suite.ts`/`incremental.ts` through a CLI bridge; refusals surface as failures. Reference evaluator driven by plan definitions.

S1 → S2, S3 for the IR; S4 → S2, S3 for the schema; S5 → everyone for the gate. S2 and S3 start on day one against Spike A's and Spike B's existing forms.
