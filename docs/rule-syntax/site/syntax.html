Rerail logic: rules as Datalog

A proposal to replace the rerail.policy/v1 JSON with one text format. Each rule file is a small Datalog program over facts the parser provides. The name resolution, import and call libraries that rules depend on are Datalog too, so they ship as data instead of as binary code.

A rule file

Directives first, then the program. A rule defines relations with :- and declares the findings it reports with .violation.

Relation names in a code view are links. Click one to see its definition. Blue names come from a Datalog library and orange names are native.

.policy "bandit-b102-exec-used" revision 3 .description "Avoid exec() calls, including through import aliases." .language python .mode steer .scope include "**/*.py" .use python/names .violation B102(at: node) "Replace this exec call with code that performs the operation directly." suppress nosec "B102" B102($c) :- kind($c, "call"), field($c, "function", $f), sym_of($f, "builtins.exec"). B102($c) :- kind($c, "call"), field($c, "function", $f), kind($f, "parenthesized_expression"), child($f, $g, 0), sym_of($g, "builtins.exec").

Directives

Directives are one per line, so tools can rewrite one without touching the logic. Approving a rule changes .mode, and a ratchet changes .budget.

Bodies

A body is a comma-separated conjunction. Each alternative is its own rule. Negation is stratified. Values come from @ builtins and are never used as body atoms.

host_tag($t) :- kind($t, "identifier"), $t =~ "^[a-z]". // regex on a node's text stop($n) :- kind($n, $k), $k in barrier. // set membership stop($e) :- kind($e, "jsx_element"), !router_el($e). // negation stop($e) :- kind($e, "jsx_element"), !(field($e, "open_tag", $o), host($o)). // negated conjunction narrow($i) :- import_stmt($i), !some { within($i, $b), type_checking_block($b) }. single($b) :- kind($b, "block"), $k = count { child($b, _, _) }, $k = 1. qualname($f, @cat($m, $x)) :- def_name($f, $x), nearest($f, $s, scope), modname($s, $m). FUNCTION_IMPORT($i, $c) :- local_import($i), $c = first { "typing-only" if !value_read($i); "test-helper" if test_fn($i); "other" }.

From JSON to .rr

Every JSON construct has a fixed lowering. The tree axes become native tree builtins: within is "below", and with a stop set it is "below, with no stop node in between". Utilities become relations. Anything without a lowering stays as a matcher atom, ast($n, {…}), and runs as it does today.

Native or Datalog

The binary provides the parse tape, tree arithmetic, value builtins and file readers. Name resolution, imports, call targets, JSX structure and typing are Datalog libraries over those. A library update ships without a new binary.

  • core: native. Tape relations, within, nearest, config readers.
  • python/names, python/imports, python/calls: lifted from Typing-support's calls.rdl.
  • tsx/names, tsx/jsx: drafted for this page.
.use python/names // scope_node, binding, ref_site, sym_of, annotation, catches, … .use python/imports // import_alias, loads, runs, reaches, exports, public_name, … .use python/calls // call_target, call_open, reach, call_arg, awaited, … // core (native): kind, field, child, text, value, within, nearest, line, doc, file, tsconfig_path, …

Unknown is not false

A relation declared must, may has two sides. In a definite derivation, a negation reads the may side, so a definite finding never rests on an unknown. Findings reached only through may keep their code, carry a possible tag, and use .possible's mode.

.decl passes(e: node) must, may must passes($e) :- tag($e, $t), host_tag($t). must passes($e) :- tag($e, $t), sym_of($t, $q), component($q, $f), children_slot($f, _). may passes($e) :- tag($e, $t), sym_of($t, $q), !component($q, _). // a package with no summary
