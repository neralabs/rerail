Rerail logic: rules as Datalog

A proposal for how Rerail rules are written. It replaces today's rerail.policy/v1 JSON with one text format, .rr, and moves name, import and call resolution out of the binary into libraries written in the same format.

Why change

  • The JSON is hard to read and write. A rule is a nested matcher tree. The nested-router rule below is {{router_json_lines}} lines of JSON; the same meaning in .rr is {{router_b1_code}} lines of logic.
  • It cannot say what the data-layer checks need. They follow imports across files, count over a module graph, and compare definitions in different classes. Today they are six Python linters, {{dl_py_lines}} lines. PR 2539 tried YAML with SQL strings; its port drifted from the Python.
  • Resolution logic ships in the binary. What a name refers to, what an import loads and what a call targets are compiled into Rerail. Improving them means a new release.

What changes

  • A rule is a small Datalog program over facts the parser extracts from the code: node kinds, fields, text. Settings such as mode, scope and budgets are one-line directives at the top.
  • Libraries are Datalog too. python/names, python/imports, python/calls, tsx/names and tsx/jsx ({{lib_py_lines}} + {{lib_tsx_lines}} lines) define relations such as sym_of, "what this expression refers to". They ship as data and update without a new binary. The binary keeps the parser, tree arithmetic, file readers and the edit applier.
  • Unknown is not false. When a fact cannot be known, for example what a component from a package renders, the finding is reported as possible with its own mode instead of being guessed either way.
  • Fixes are rules. A fix is a set of edits derived from the same facts, so a rule can offer a fix only where its evidence shows the edit is safe.

{{dl_py_lines}} → {{dl_rr_code}}data-layer lines: Python → .rr logic
  • Every pack rule has a machine translation. Where a JSON construct has no .rr form yet, it stays as a ast($n, {…}) piece.
  • Six data-layer checks, function-level-imports and the router rule are written by hand in their final form, beside the Python they replace.
  • Nothing has been compiled or run: there is no .rr parser or engine yet. Known problems found by reading are listed in docs/rule-syntax/OPEN-ISSUES.md.

How to read this page

  • Syntax: Datalog from the start, then each part of the format, fixes, and possible findings.
  • Library: the Datalog libraries and the native core they stand on.
  • Pack rules: every shipped rule, today's JSON beside its .rr.
  • Data-layer rules: the hand-written rules, each beside the JSON port and the Python linter.
  • In any .rr code, relation names are links. Blue names come from a Datalog library, orange names are native, and names with a dotted underline are defined in the same file.
