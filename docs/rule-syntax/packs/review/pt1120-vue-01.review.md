for `lang="ts"`/`"tsx"`, espree otherwise; the four rules at `"error"`, no options). I read the rules at the

`return-in-computed-property.js`, `valid-v-for.js`, and `lib/utils/index.js`: `defineVueVisitor`,

`iterateReferencesTraceMap`, `isCustomComponent`) and their docs, then ran my own cases with ESLint and with

translation's output gives no column, so a finding is compared by line. ESLint's lines are `line:column`.

## `eslint-plugin-vue-no-watch-after-await`: defects

What agrees with ESLint on my cases: `watch?.()` (reported), `return watch()`, a class field initializer
`class K { x = watch() }` (both report: a field is not a function), a watch in a nested block, `watch() as any`
(reported) and `const s = watch() as any` (reported: the parent is the `as`), `x.y = watch()` (kept),
`const [p = watch()] = []` (reported), `for await` (not an await: both), `V["watch"]()` through a namespace import,
`#imports`, `"setup"` as a string key, `setup: async function`, and a free `watch()` with no import (neither
reports: `iterateGlobalReferences` finds no global `watch`).

### 1. A watch reached through an alias is missed

`ReferenceTracker` follows a variable a tracked reference is assigned to (`const w = watch`) and a destructuring of
the namespace (`const { watchEffect: we } = V`). `vvue_import_call` reads the callee's own import only.

`w-alias.vue`:

```vue
<script>
import * as V from "vue"
import { watch } from "vue"
export default {
  async setup() {
    await load()
    const w = watch
    w(a, f)
    const { watchEffect: we } = V
    we(f)
  },
}
</script>
```

```text
ESLint:      w-alias.vue 8:5   `watch` is forbidden after an `await` expression.
             w-alias.vue 10:5  `watch` is forbidden after an `await` expression.
Translation: (nothing)
```

### 2. `<script lang="tsx">` (and so every rule below that reads the script): nothing is read

`vjs`/`vts` (lib/vue/vue-01) admit a view whose guest grammar is `javascript` or `typescript`. A `lang="tsx"`
component's view is neither, so every relation the rule seeds is empty. `lang="jsx"` is read (as JavaScript).

`tsx.vue`:

```vue
<script lang="tsx">
import { watch, computed } from "vue"
export default {
  props: { a: { type: Number, default: "x" } },
  computed: { b() { if (x) return 1 } },
  async setup() {
    await load()
    watch(a, f)
    const c = computed(() => { if (x) return 1 })
  },
}
</script>
```

```text
ESLint:      tsx.vue 4:40  require-valid-default-prop    Type of the default value for 'a' prop must be a number.
             tsx.vue 5:16  return-in-computed-property   Expected to return a value in "b" computed property.
             tsx.vue 8:5   no-watch-after-await          `watch` is forbidden after an `await` expression.
             tsx.vue 9:24  return-in-computed-property   Expected to return a value in computed function.
Translation: (nothing)
```

The same file with `lang="jsx"`: ESLint and the translation both give all four.

### 3. A v-for alias the view cannot parse drops the component's script (see valid-v-for 2)

`v-empty-noparen.vue` (valid-v-for §2): ESLint reports the watch at 10:33 and the getter at 9:16; the translation
reports neither.

## `eslint-plugin-vue-require-valid-default-prop`: defects

What agrees: d9-style defaults (`() => "x"` for Number at the body, `Number("1")` for String, `1n` for Number,
`default() { return [] }` for Object, `async () => ({})` for Array, a factory returning a function for String), a
prop value `{ … } as any` (read by both), `-1` and `undefined` (neither), `[Number, null]`, `"type"`/`"default"` as
string keys (neither), a nested function's `return` inside a factory (ignored by both), `defineModel(…, { … } as any)`.

### 1. Props declared by a TypeScript type are not read

The header says so (`defineProps<T>()`, `defineModel<T>()` "need type inference"), but the plugin's
`inferRuntimeType` reads type literals and keywords without a type checker, and ESLint reports these with the
default config (no `parserOptions.project`). This is the common `<script setup lang="ts">` form.

`d-typed.vue`:

```vue
<script setup lang="ts">
const p = withDefaults(defineProps<{ n?: number, s?: string, o?: object }>(), { n: "x", s: 1, o: {} })
const m = defineModel<number>("m", { default: "x" })
</script>
```

```text
             d-typed.vue 3:47  Type of the default value for 'm' prop must be a number.
```

### 2. A block-bodied factory in withDefaults' second argument is checked; ESLint never checks it

The plugin collects a block factory's `return`s in `':function'` of `defineScriptSetupVisitor`, which looks at
`scriptSetupPropsContexts.at(-1)`: the context is pushed on `onDefinePropsEnter` and popped on `onDefinePropsExit`,
when the `defineProps(…)` call ends. withDefaults' second argument is visited after that, so its block factories
have no context and their returns are not checked. (An expression-bodied arrow is checked at once, in
`collectDefaultContext`, and both report it.) The translation's block clause takes every source but `assignment`.

`d-withdefaults-block.vue`:

```vue
<script setup>
const p = withDefaults(defineProps({ b: Array, c: Object }), { b: () => { return 1 }, c: function () { return [] } })
</script>
```

```text
ESLint:      (nothing)
Translation: d-withdefaults-block.vue:2  Type of the default value for 'b' prop must be a array.
             d-withdefaults-block.vue:2  Type of the default value for 'c' prop must be a object.
```

`getComponentPropsFromOptions` takes the `props` property only when its value is an object or array as written.

`d-props-as.vue`:

```vue
}
</script>
```

```text

Translation: d-props-as.vue:4  Type of the default value for 'a' prop must be a number.
```

## `eslint-plugin-vue-return-in-computed-property`: defects

What agrees: try/finally, `try { return x }`/`return a + b`/`return this.x`/`return new X()` with an empty catch
(reported: an identifier, member, call or `new` can throw), `try { throw 1 } catch {}`, `if (true) return 1`
(reported: ESLint does not fold an `if`), labelled `while (true)` with `break lbl`, `return;` last,
`computed({ get: function () {} })`, an Options API `{ get: () => {} }` (neither), a comment as the first statement,
`lang="jsx"`, and a free `computed()` with no import (neither).

### 1. A comment between statements ends the walk: false positives

`vfirst_stmt` skips non-statements, but `vnext_stmt(c, d)` is `next_sibling(c, d)` with both statements: a comment
between two statements has no `vnext_stmt`, so `vcompletes_from` stops at the statement before it and the block
"completes". The same in a switch: `vlast_case` takes the body's last child, a trailing comment, which has no
`body`, so the switch completes.

`r-comments.vue`:

```vue
<script>
export default {
  computed: {
    a() {
      const x = load()
      // the cached value wins
      return x
    },
    b() {
      switch (x) {
        case 1: return 1
        default: return 2
        // end
      }
    },
    c() {
      if (x) return 1
      else /* otherwise */ foo()
    },
    d() {
      const x = 1 /* why */
      return x
    },
    e() {
      const x = 1 // why
      return x
    },
  },
}
</script>
```

```text
ESLint:      r-comments.vue 16:6  Expected to return a value in "c" computed property.
Translation: r-comments.vue:4     Expected to return a value in "a" computed property.
             r-comments.vue:9     Expected to return a value in "b" computed property.
             r-comments.vue:20    Expected to return a value in "d" computed property.
```

`a`, `b`, `d` are false positives. `c` is a miss: `vcompletes` of an `if` reads the `else_clause`'s child 0, which
is the comment (not a statement, so it never completes), and the `else` branch is taken as leaving the function.
(`e`'s line comment does not trip it.)

### 2. Loops with a constant test other than `true`

ESLint's code path analysis treats a loop whose test is any literal that is truthy (`getBooleanValueIfSimpleConstant`)
as endless, in `while`, `for` and `do … while`. vue/flow's `vtrue_cond` accepts the literal `true` only, in `while`
and in no `for` condition, and a `do … while` always completes when its body does.

`r-loops.vue`:

```vue
<script>
export default {
  computed: {
    a() { while (1) { if (x) return 1 } },
    b() { while ("go") { if (x) return 1 } },
    c() { for (; true;) { if (x) return 1 } },
    d() { do { if (x) return 1 } while (true) },
  },
}
</script>
```

```text
ESLint:      (nothing)
Translation: r-loops.vue:4, :5, :6, :7  Expected to return a value in "a" / "b" / "c" / "d" computed property.
```

`r-key.vue`:


```text
ESLint:      r-key.vue 4:8  Expected to return a value in "Unknown" computed property.
Translation: (nothing)
```

### 4. computed()'s getter through `as`, `satisfies` or `!`

`getGetterBodyFromComputedFunction` takes the first argument (or the `get` property's value) only when it is a
function as written. `vcomputed_fn` and `vgetter` `vunwrap` it.

`r-cast.vue`:

```vue
<script setup lang="ts">
import { computed } from "vue"
const a = computed((() => { if (x) return 1 }) as any)
const b = computed({ get: (() => {}) as any })
const c = computed(function () { if (x) return 1 }!)
</script>
```

```text
ESLint:      (nothing)
Translation: r-cast.vue:3, :4, :5  Expected to return a value in computed function.
```

### 5. A catch reached before anything in the try block can throw (minor)

ESLint connects a catch block only from the first throwable point of the try block (a call, member access,
identifier, `new`, `throw`…). vue/flow takes every handler as reachable.

`r-try.vue`:

```vue
<script>
export default {
  computed: {
    a() { try { return 1 } catch (e) { } },
  },
}
</script>
```

```text
ESLint:      (nothing)
Translation: r-try.vue:4  Expected to return a value in "a" computed property.
```

The same for `while (true) { try { return 1 } catch (e) { break } }` and `try { return 1 } catch (e) { log() }`.

## `eslint-plugin-vue-valid-v-for`: defects

What agrees: `of` with a space, `(a, b, c, d)` (neither), `(a, [b])` and `(a, {b}) of xs` (invalid alias), a
modifier, `v-for:arg`, `<component :is>` and `is="vue:foo"` without a key (custom), `a, i in xs` with no
parentheses.

### 1. No space between the alias's `)` and `in`/`of`: the :key is reported

vue-eslint-parser splits the alias at `in`/`of` after whitespace or `)`. The view does not read `(a, i)in xs` as a
v-for, so `for_var` has no variables and every :key is "not using" them; `alias_text` needs whitespace too, so an
empty alias there is not reported either.

`v-nospace.vue`:

```vue
<template>
  <div>
    <li v-for="(a, i)in xs" :key="i" />
  </div>
</template>
```

```text
ESLint:      (nothing)
Translation: v-nospace.vue:3  Expected 'v-bind:key' directive to use the variables which are defined by the 'v-for' directive.
```

`v-empty-nospace.vue`, `<li v-for="(, i)in xs" :key="i" />` on line 3:

```text
ESLint:      v-empty-nospace.vue 3:16  Invalid empty alias.
Translation: v-empty-nospace.vue:3     Expected 'v-bind:key' directive to use the variables which are defined by the 'v-for' directive.
```

Same line, different finding.

### 2. An alias without parentheses: holes and patterns are not checked, and a hole drops the view

`alias_text` matches only `( … ) in …`. vue-eslint-parser reads `, i in xs` and `a, {b} in xs` as the same aliases
as their parenthesised forms. With a hole, the view (vue/view) loses the component: the :key is reported, and
the script rules see nothing in the file (no-watch-after-await §3).

`v-empty-noparen.vue`:

```vue
<template>
  <div>
    <li v-for=", i in xs" :key="i" />
  </div>
</template>
<script>
import { watch } from "vue"
export default {
  computed: { b() { if (x) return 1 } },
  async setup() { await load(); watch(a, f) },
}
</script>
```

```text
ESLint:      v-empty-noparen.vue 3:16   valid-v-for                  Invalid empty alias.
             v-empty-noparen.vue 9:16   return-in-computed-property  Expected to return a value in "b" computed property.
             v-empty-noparen.vue 10:33  no-watch-after-await         `watch` is forbidden after an `await` expression.
Translation: v-empty-noparen.vue:3      valid-v-for                  Expected 'v-bind:key' directive to use the variables which are defined by the 'v-for' directive.
```

`v-alias-noparen.vue`, `<li v-for="a, {b} in xs" :key="a" />` on line 3:

```text
ESLint:      v-alias-noparen.vue 3:19  Invalid alias '{b}'.
Translation: (nothing)
```

(`a, , i in xs` is the same as `, i in xs`. In one template with other v-fors, such an alias also gave a :key
finding on every other v-for of the file.)

### 3. A dynamic argument: missed

`'v-for' directives require no argument.` is reported when `node.key.argument` is set, a `VExpressionContainer` for
`v-for:[arg]`. The translation looks for a `directive_value` child only, and a dynamic argument is a
`dynamic_directive_value`.

`v-dynarg.vue`:

```vue
<template>
  <div>
    <li v-for:[arg]="x in xs" :key="x" />
  </div>
</template>
```

```text
ESLint:      v-dynarg.vue 3:15  'v-for' directives require no argument.
Translation: (nothing)
```

Messages: the three empty-alias messages ("Name the empty value alias in this v-for, …") are not the plugin's
(`Invalid empty alias.`, for each of value, key and index); the author's notes say they were kept on purpose. The
lines agree (`3:16` against `:3` above).
