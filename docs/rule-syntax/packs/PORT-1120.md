## Writing a rule in #1120's shape

A program runs in two parts: a per-file part, derived again for each file an edit changes, and a cross-file part,
kept up to date over the whole repository (decisions 0691, 0710). What the per-file part hands across is paid for at
every edit of every file it came from, so a rule is written to stay per file and crosses only where it must, by
declaration.

1. **The per-file part is the default.** A relation whose rules read one document's rows (`kind`, `field`, `text`,
   `child` of the same file's nodes) is per file. It may also join settings and stay per file: a relation declared
   `setting` (`env`, `file`, `option`), `keyed` (column 0 names a folder, target or module: `package`, `tsconfig`,
   `tsx_names__exports`) or `by_path c` (a row per file, its path in column 0: `package_for`, `tsconfig_for`,
   `node_resolve__file_at`). A phase's answer is read at the file's own path:
   `doc(d, p, _), node_resolve__file_at(p, x, st, f)` (`lib/tsx/node-resolve.rerail`).
2. **Tables are keyed by node.** A table computed from a node's text is keyed by that node, not by the text. A table
   keyed by a name is every file's names in one relation: it joins documents, so it crosses (0652), and an edit of one
   file changes it for every reader.
3. **A crossing is declared and carries no node.** Where a rule needs every file (the corpus's modules, every
   import), the relation is declared `.decl r(...) cross_file` and keyed by symbols, paths or values: never a node,
   a value computed from a node (0677), or a position (`line`, `col`, `node_order`, 0649). Each file's own rules then
   relate its nodes to that relation.
4. **No join of two documents' rows.** A guest document (an embedded script, a template) reaches its host by node
   (`host_node`), not by matching `guest` rows of the two documents.
5. **Every input has a producer** (0710): an input nothing gives rows is an error. Include the library that declares
   it: `tsx/project.rerail` for `tsconfig`, `tsconfig_for` and `tsconfig_path`; Python's module privacy reads
   `file(cat(dir, "/__init__.py"))`, not `py_unpackaged` (removed).

`RERAIL_SHOW_CROSSINGS=1` prints each crossing the split finds with its rule; `RERAIL_STRICT_CROSSINGS`,
`RERAIL_STRICT_NODES` and `RERAIL_STRICT_POSITIONS` refuse the program instead.

**Example 1: a table keyed by node** (`packs/javascript/eslint-sort-keys.rerail`). The old translation keyed its sort
key by the property's name, through a set of every name:

```
.decl sort_key(x: symbol, k: symbol)
sort_key(x, k) :- named(x), !option("natural", "true"), cased(x, c), units(c, k).
.decl named(x: symbol)
named(x) :- pname(_, x, _).
```

`named` is every file's property names in one relation, so `sort_key` crossed. In #1120's shape each table is
keyed by the property node, and the rule reads it at that node:

```
.decl sort_key(p: node, k: symbol)
sort_key(p, k) :- !option("natural", "true"), units(p, k).
.decl cased(p: node, c: symbol)
cased(p, x) :- pname(p, x, _), !option("caseSensitive", "false").
.decl units(p: node, u: symbol)
units(p, c) :- cased(p, c), !match("[\\s\\S]*[\\x{10000}-\\x{10FFFF}][\\s\\S]*", c).
```

**Example 2: a declared crossing** (`lib/python/modules.rerail`). Which file a module name means depends on every
file's imports and on the corpus's own modules. Each file finds its imports per file (`py_import(i: node, q:
symbol)`); only the module names cross, as symbols, declared:

```
.decl py_want(q: symbol) cross_file   // every file's imports, as one set (decision 0652)
py_want(q) :- py_import(_, q).
.decl py_workspace(q: symbol) cross_file   // the corpus's modules (decision 0652)
py_workspace(q) :- py_docmod(_, p, q), !loaded(p, _, _).
```

The resolution (`py_resolves(q, f, layer)`) is computed over those symbols; a file's rule joins it back to its own
import node through `py_import(i, q)`.
