# LEG-083: what the port found, and a patch for the data layer

LEG-083 (`scripts/lint_legacy_execution_surfaces.py`) reports a function that reaches an eager lazy-terminal
`resolve()` through calls in its own file, unless a legacy surface is on the way. Porting it to `dfs_first`
(data-layer/DESIGN.md, addition 7) meant checking the port against the script on the real repository. That
found three problems in the script itself. This note records them, the evidence, and a patch
(`LEG-083.patch`, against commit 2b1504adc4, 2026-10-18). The patch is not applied: the data-layer
repository is read-only from here.

## 1. Any method named `resolve` counts as eager

The collector records every `x.resolve(...)` and `x.resolve_async(...)` call (on_Call, line 486). The lazy
terminals are `LazyResult.resolve(self)`, `LazyResult.resolve_async(self)` and the `LazySeq` pair: they take no
arguments. Other calls of that name are a pathlib path resolving itself, or a lookup:

```python
path = path.resolve()                          # l1100_exceptions/safe_file_ops.py: pathlib
return Path(source_file).resolve()             # scripts/generate_rust_intents.py: pathlib
catalog.resolve(MatchRowTypeRef(value))        # l1470_matching_contracts/registry.py: a catalog lookup
return self._lookup.resolve(txn)               # l9875_mcp/session.py: builds a LazyResult
```

Calls in LEG-083's own files (`_is_internal_execution_path`), by kind:

| Commit | Lazy-terminal shape | On a pathlib path | With arguments | `--check` findings | Real |
|---|---:|---:|---:|---:|---:|
| 41ab36f, 2026-08-20 | 66 | 24 | 6 | 56 | 40 |
| 2b1504a, 2026-10-18 | 0 | 20 | 6 | 18 | 0 |

At the October commit every LEG-083 finding is a false positive. Every call classified as a lazy terminal
in August is one (`txn.select_one_lazy(…).resolve()`, `query_lazy(…).lazy().resolve_async()`, …), and
every call classified as a path is one.

The fix: count a call only if it has no arguments and its receiver is not a path. Which names hold a path
is inferred per scope, approximately: a parameter or annotated assignment whose annotation mentions a
pathlib class, or an assignment from a path expression (`Path(x)`, `p.parent`, `p / "x"`,
`p.with_name(x)`, `a if c else b`, …), looked up through enclosing scopes as Python does. Attributes
(`args.root`, `self.path`) are not followed. Over the whole repository, about 50 of 1,293 lazy-shaped calls
still have a path-like receiver name; all but one are in `scripts/`, tests or `conform/`, which LEG-083 does
not check.

## 2. The shared memo makes findings depend on function names

The script searches the functions of a file in `sorted(symbol)` order with one memo for all of them
(line 1235). A search skips a function still open on its own path; when that makes a function fail, the
failure is memoised, and every later function that reaches the eager call only through it is not
reported. The test the patch adds is the smallest case:

```python
def a(server_plan):
    b(server_plan)            # b calls only a, which is open: b is memoised as reaching nothing
    return eager(server_plan)

def b(server_plan):           # not reported, though b -> a -> eager
    return a(server_plan)

def eager(server_plan):
    return server_plan.execute_lazy().resolve()
```

Renaming `b` so it sorts before `a` makes it reported. On the whole repository (every `.py` file, LEG-083's
rules) the memo loses 34 functions, all in one group of renderers in `scripts/generate_rust_intents.py`
that call each other. Their eager call is a pathlib `resolve()` (problem 1), so with the corrected eager
test the memo loses nothing on today's code: 1,234 findings either way. It stays a latent bug for the first
cycle that reaches a real lazy terminal.

The fix: one memo per root. Within one root's search the memo still marks finished functions, so each
function is entered at most once per root. The search costs about 2.5 times the steps (134,530 to
331,223 in LEG-083's files, a few hundred milliseconds of Python at most), and findings no longer depend on
names. This is `dfs_first`'s meaning; the Rerail port computes it set-based, without a search per root.

## 3. The two entry points check different files

`--check` (`scan_repo`) scans the whole repository, and LEG-083 keeps the files `_is_internal_execution_path`
accepts. The lint-all plugin (`build_plugin`) reads only 14 directories (the raw-transaction and
raw-cursor scopes, the post-fetch-filter scopes, `l2050_transaction`, `l7200_versioned_transactions`,
`l9900_auto_api`, …). At the August commit, lint-all reports 10 LEG-083 findings and `--check` 56:

| Commit | lint-all: script | lint-all: fixed | `--check`: script | `--check`: fixed |
|---|---:|---:|---:|---:|
| 41ab36f | 10 | 0 | 56 | 40 |
| 2b1504a | 0 | 0 | 18 | 0 |

Lint-all's 10 are all false positives, and the 40 real findings are all outside its directories
(`l4250_timers/timer.py` 21, `l3200_metadata/bootstrap_state.py` 8, `data_layer/ipc.py` 7, …). Whichever
entry point gates a merge, it got LEG-083 wrong in August. The patch does not change the plugin's scope,
because the scope is shared by every LEG code. Giving LEG-083 its own scope, `_is_internal_execution_path`,
would make the two agree.

## Evidence

- **The copy of the script.** spikes/dfs-first/realgraph.py rebuilds the script's facts from `git
  cat-file` and `ast` and runs a copy of `_transitive_eager_resolve`. Nothing from the repository runs.
- **Ground truth.** The data-layer worktree holds the lint-all run's fact cache for 41ab36f
  (`tmp/lint_fact_store`, keyed by the source's sha256). On all 355 files the cache covers,
  spikes/dfs-first/vs_cache.py finds the same LEG-083 rows as the copy (10 findings).
  spikes/dfs-first/plugin_scope.py shows the 355 files are exactly lint-all's directories, which accounts
  for the run's count (`legacy_execution_surfaces FAIL 18`, all LEG codes).
- **The port.** For all four versions (the script, a fresh memo, the corrected eager test, both), the
  set-based plan gives the copy's answer on every root: 61,403 roots in LEG-083's files, 152,753 over every
  file, 44,811 at the August commit. This holds sequentially, on 8 threads and on the GPU
  (`cargo run --release -- real GRAPH`).
- **The patch.** It applies cleanly at 2b1504 (`patch -p1 --dry-run`) and compiles. Its helpers classify
  the new tests' calls as expected, and the cycle test fails with the shared memo and passes with one memo
  per root (checked with the copy). The data layer's own suite has not been run on it.

## The patch

`LEG-083.patch` changes `scripts/lint_legacy_execution_surfaces.py` and its tests:

- `_PathScope`, `_scope_nodes` and `_is_lazy_terminal_call`: the eager test of problem 1;
- `_path_scope_stack` on the collector, pushed in `_enter_function` (which now takes the traversal context,
  to reach the module) and popped in `_exit_function`;
- `on_Call` records an eager line only for a lazy terminal; other `resolve` calls are still not call
  candidates, as before;
- the per-file `eager_memo` becomes one memo per root;
- four tests: pathlib on an annotated parameter; on module and constructed paths; `resolve` with
  arguments; and the cycle case.

Signing is unaffected: the allowlists do not change.
