# O78: the hand-written data-layer rules against their recorded findings

## Intro

Each rule in this directory ports one Python linter from the data-layer repository. The reference for a
rule is the set of findings that linter recorded on its fixtures, keyed by (path, line, code). The
final-shape branch's open item O78 listed the events where the rules miss those findings. This note says
what changed in the rules to close those misses, why, and how many events are exact before and after.

The rule is parity with the linter. Several rule headers used to list ways the port "improves on the Python
linter". Wherever such an improvement changes a recorded finding, the rule now does what the linter does.

## What changed

**swallowed-exceptions.rr.** `with … suppress(…)` is now matched by the callee's text, exactly as
`lint_swallowed_exceptions.py` does it. Nothing is resolved, and the header says that the text decides.
The linter tests each with-item twice, and the rule models both tests:

- `legacy_suppress`: in a plain `with` only, not `async with`, the callee's `_get_dotted_name` text is
  `contextlib.suppress` or `suppress`. This test skips a call whose joined argument names are one protocol
  exception.
- `suppress_call`: the callee is `contextlib.suppress` on the bare name `contextlib`, or it is a bare
  `suppress` while the last `from contextlib import …` before the `with` imports `suppress`. This is the
  linter's `has_bare_suppress`, which every contextlib from-import resets, wherever that import is. This test
  skips only `suppress(KeyError)`.

So an aliased `suppress as s` is no longer matched, and an unimported `contextlib.suppress(…)` or
`suppress(…)` is.

The nested-handler probe is not a recording artefact. The linter really reports line 7: its
`_nested_scope_depth` drops every raise that sits inside a def, class or lambda within any handler. The
plugin event of the same source records `[]` because it is the signed aggregate baseline reporter
(`retained_reason`), not a per-finding one. The rule now follows the linter: a raise below such a scope
counts for no handler (`hidden_raise`).

**layer-violations.rr.** `tc_if` is the linter's `is_type_checking_block`. The rule now uses it instead of
names.rr's resolved `type_checking_block`:

- An `if` whose condition is the bare name `TYPE_CHECKING` (parentheses aside) counts, whether it is
  imported or not.
- `typing.TYPE_CHECKING` and `not TYPE_CHECKING` do not count.
- Every branch is exempt: the body, `elif` and `else`.
- An `elif TYPE_CHECKING:` exempts its own clause and the clauses after it, as the nested `ast.If` does.

**missing-async-pairs.rr.** The "Improves on the Python linter" design is gone:

- Only the arguments in `node.args.args` are compared and tested for connection-like names. Positional-only,
  keyword-only, `*args` and `**kwargs` are left out. The rule computes this locally (`pos_param`), because
  python/ast.rr's `sig_param` does not lower to the engine yet.
- A class is its name within one file.
- The last def on a side wins (`member`), as the linter's dicts do.
- Inherited counterparts no longer count.

**post-op-no-internal-dispatch.rr.** POSTOPDISPATCH001 already uses `earlier`: commit 6f5bc564c, made while
this work was under way, changed it from `precedes`. That is the linter's collector order (first visited
comparison). rrlab confirms that `precedes` reported twice across two `if`s and `earlier` reports once.

**Tooling, for the checks:**

- `lib/python/calls.rr`: a variable named `as` was renamed `al`, because Soufflé (rrlab) rejects it.
- `tools/rrlab/rrlab.py`: a `.violation` without a `code` clause has its own name as its code, as in the
  engine.

## Verification

- `site/check_rr.py` prints ok.
- **rrlab on small cases** built from the linter's behaviour, each compared with the linter run on the same
  files:
  - swallowed-exceptions: 29 files, identical.
  - layer-violations: 10 files, identical on api_impl. rrlab gives no layer_dependency rows, an rrlab gap.
  - missing-async-pairs: 14 files, identical. The old rule had 7 extra findings.
- **rrlab on real repository files**, compared with the linter:
  - swallowed-exceptions: the 19 files that use `suppress(`. 66 of 66 findings match. The old rule missed 5,
    all unimported `contextlib.suppress`.
  - layer-violations: 40 conform/ files with TYPE_CHECKING. 25 of 25 match, before and after.
  - missing-async-pairs: the 42 transaction files. The linter has 0 findings; the new rule has 0 and the old
    one had 3 signature_mismatch.

- Regex `\.` in strings, which Soufflé rejects.
- A `.scope include` continued on a second line.

## Left

- **post-op-no-internal-dispatch, 5 events.** names.rr's `cmp` reads `op(c, o)`, and the engine's `op` has no
  comparison operators (O79). wolfeel's copy reads `op_at(c, 0, o)`. That change belongs to the core.rr
  alignment.
- **public-api-triples, 4 events.**
  - literal-exports-16 and -21 need imports.rr's `has_all`: `__all__ = []` means no public names. wolfeel has
    this change; here it waits for approval to edit imports.rr.
  - chainable-builder needs `text` of any node in the engine.
  - property-override-inherits-public needs a decision on the property-override case.
- **swallowed-exceptions still differs from the linter where no recorded finding shows it** (listed in its
  header):
  - Caught types are resolved, where the linter compares their text.
  - The exception variable is followed by binding, where the linter matches any `Name` at depth 0 of the
    innermost handler.
- **layer-violations still resolves relative imports**, where the linter drops the dots.
