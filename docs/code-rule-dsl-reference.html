Rerail code-rule DSL reference

Every construct of rerail.policy/v1: the rule keys, relations, combinators and predicates the native engine compiles, with their JSON shape, semantics, capture behaviour, three-valued behaviour, soundness under syntax errors, language support and limits, each mapped to the rule documents committed in the rule packs and the bundled code rules. For complete, tested rules that hold a codebase's design in place, start with the architecture rule examples.

Sources of truth. Accepted JSON: src/engine/code-rule/code-rule-schema.ts (zod) and src/engine/code-rule/code-rule.ts (types). Semantics: native/src/code_rule_dsl/. Every example below is either quoted from a code-rule document (its path and JSON pointer are printed above it; Ruff and ESLint ports come from conformance suites that are not part of this repository) or written for this page; each one that is not marked fragment compiles with the engine at this commit (scripts/generate/docs/code-rule-dsl-reference.mjs examples).

1. Overview #

What a code-rule document holds, which languages it reads, and how the engine evaluates it.

Documents, clauses, violations #

A code-rule document is one JSON object:

  • format: always "rerail.policy/v1";
  • id and a positive integer revision;
  • optional description and scope (path globs);
  • a non-empty list of clauses.

The catalog stores one document per row of ~/.rerail/rerail.sqlite; each top-level field is a column, so everything else lives in clauses. A clause has an id unique in its document and exactly one form:

FormWhat it holdsWhat it reports
forbida query: ast, regex, file, or select_whenone violation per witness (per binding with each)
require_eachtwo evidence relations, subject and evidenceeach projected subject without evidence
budgetan evidence relation, group_by keys and count.ltegroups over the budget
relationalevidence relations as tables, optional parser-node and reference tables, and ordered SQL stageseach row the final query returns
llmanything (the schema reads unknown)reserved
defineshared utils, options and config, and a document-wide report_whennothing: it has no violation; a document needs a clause beside it

Every clause but a define has a violation: a code, an anchor, a message template, and optionally fix, each, suppress. The document's mode decides what happens to it:

  • log records it.
  • steer reports it to the agent.
  • block acts like steer until block enforcement lands.

A fix is only a suggestion: Rerail never applies it.

Most rules are forbid clauses over an ast query: a language, a rule object matched at each candidate node, and options (utils, constraints, transform, languageOptions, when, file). A rule object is ast-grep 0.45.3's rule language (the pinned ast-grep-core) plus Rerail's name resolution, values, arguments, sub-grammars, layout, counting and comparison.

Languages come from the registry (languages/*.json, see docs/language-packs.md):

  • Planned language: stored, but refused at compile time with language-not-supported; the catalog keeps the rule inactive until the engine reads it.
  • not-supported-yet capability: its predicates are refused likewise.
  • refused capability: its predicates are invalid.

Rerail follows one language standard: a code-rule language names the dialects it compiles for; its family supplies semantics. PHP. PHP-only files; .blade.php templates use Blade.

  • Values: PHP 8.5 constant expressions. eq is ===; compare orders as PHP's operators. follow reads the one binding every path gives a variable, and the file's constants.
  • Arguments: bound as PHP binds them, named arguments and literal ...[...] unpacking included. mode: "syntactic": by name, else by position before the first unpacking (Ruff's find_argument on PHP-Parser's args).
  • Names: classes, functions and constants as PHP-Parser's NameResolver (resolves: { import, prefix }).
  • Variables: a flow over control flow. resolves.unresolved: no path defines the read (PHPStan's variable.undefined). resolves.global: superglobals. Usage as Psalm's unused-variable analysis; the dynamic symbol table is unknown.
  • Bindings: forms assignment, augmented, for, except, parameter, global, static; scopes global, function, closure.
  • Compare: key, member, name, reference, reference-no-static-keys, structure, structure-hash, per nikic/PHP-Parser 5.9.0 and PHP 8.5 conversion and name lookup (the modes).
  • Calls: calls follows the workspace's functions and methods.
  • Formats: printf strings are printfFormat trees (PHP 8.5.11's php_formatted_print); formatArgs style printf reads sprintf, printf, fprintf, v*printf as PHP and PHPStan's argument.sprintf do. sscanf/fscanf strings are scanfFormat trees (PHP 8.5.11's ValidateFormat); style scanf reads their variables.
  • Doc comments: phpDoc trees (phpstan/phpdoc-parser's AST, as PHPStan 2.2.16 reads it: tags, types, variables and descriptions).
  • Suppression: suppress.phpstan, suppress.psalm, suppress.phpcs. Blade templates honour none, since no linter reads a template's {{-- --}} comments.
  • Refused: structure-parts (PHP has no implicit string concatenation), mode: "estree" (ESLint's node.arguments of ESTree), Python's format grammars and styles (naming PHP's counterpart), annotation (PHP holds no type in a string: its declared types are syntax, its PHPDoc types phpDoc).

Blade. Every semantic predicate but suppress reads the view: the PHP that illuminate/view 13.34.0's BladeCompiler compiles the template to. It holds echoes, directive arguments, @php blocks, <?php ?> tags and bound component attributes, in the template's control flow, each mapped back to its template bytes.

  • Template or view: a Blade rule matches the template with Blade's kinds; with ast.embedded: "compiled-view", the view with PHP's. embedded and host cross between them.
  • Comments: template comments ({{-- --}}, <!-- -->) in a Blade rule; PHP comments under ast.embedded, where kind: "comment" with parse: { grammar: "phpDoc" } reads doc comments (Comments).
  • Patterns under ast.embedded are PHP (sprintf($F, $$$A)); a contextual pattern selecting a metavariable is refused.
  • Defined: $loop, $message, $value and @inject variables, where Blade defines them.
  • Unknown: top-level view data; variables after @props or @aware; tokens Blade writes but the template lacks (@unless's !(); top-level calls through $this, self::, static::.
  • Refused, naming blade and why, as on PHP: structure-parts, mode: "estree", stopAtGlobal: false, resolves.write, sameImport, exported, builtin, directives, Python's format grammars and styles, annotation, languageOptions.
  • Tested by fixtures/blade/blade/: 212 regions, 78 PHPStan reports over 154 reads, 49 constant expressions, 19 templates. 14257 of 14257 copied bytes agree over 128 Laravel templates.

Vue. resolves, binds, value, compare and arguments read the program, with TypeScript's semantics. The program is the <script> and <script setup> blocks (as @vue/compiler-sfc 3.5.43 compiles them) plus template expressions (in @vue/compiler-dom 3.5.43's scopes), without render-function code. It is TypeScript for lang="ts", TSX for lang="tsx", else JavaScript; coffee and other languages embed nothing.

Script content and template expressions are copied byte for byte, each node mapped to its component bytes; generated syntax maps to the Vue construct it stands for. In source order:

  • Script block: ; over its start tag (which tells blocks apart), its content, ;.
  • HTML template: a block { … } over the template element, then per node in document order:
    • (E);: an interpolation {{ E }}, a directive value (:x="E", v-model, v-on="{…}", a custom v-foo…), or a member or function v-on handler;
    • (() => { S });: an inline handler ($event is an unresolved read);
    • (A);: a dynamic argument [A];
    • (x);: a value-less :x (Vue 3.4 shorthand, camelized);
    • if (C) { … } else if (C2) { … } else { … }: a v-if, v-else-if, v-else chain;
    • (SRC), (ALIAS) => { … };: a v-for, around its element (inside a v-if on the same element, as in Vue 3);
    • (P) => { … };: slot parameters (v-slot, #name, slot-scope, scope on a <template>), around the children;
    • Tag; or Ns.Tag;: a component tag that is an identifier or dotted chain (<ElTable.TableColumn> is one tag, as vue-eslint-parser reads it).

Text, static attributes, comments and v-pre elements write nothing.

  • Component or program: a Vue rule matches the component with Vue's kinds (element, start_tag, directive_attribute, interpolation…); with ast.embedded: "script-block", the program with its dialect's. embedded and host cross between them. Comments and patterns split the same way; embedded patterns are TypeScript and match every program dialect.
  • Unspelled tokens: a node holding a token the view writes but the file lacks (an interpolation's parentheses) is not spelled.
  • Refused: calls, formatArgs (as on ECMAScript: vue-eslint-parser hands the scripts to ESLint, which has neither) and all TypeScript refuses. languageOptions and when take TypeScript's keys.
  • Suppression: suppress.eslint: ESLint directives in script comments and eslint-plugin-vue 10.11.1's template directives (vue/comment-directive).
  • Shared scope: both scripts share module scope, as in vue-eslint-parser 10.4.1. A <script> read of a <script setup> name resolves to it.
  • Shorthand: the identifier spans its argument (aria-label) and reads camelized (ariaLabel).
  • Template syntax errors leave the program whole: an ast.embedded: "script-block" query, even a source-incomplete one, runs unless the program has its own. The file gets source-partial; the program holds what tree-sitter-vue recovers.
  • Parser quirks: tree-sitter-vue reads :a :b as one attribute (the view reads the first) and </A.B> as a syntax error.
  • Tested by fixtures/vue/language/view/: 74 template regions and 80 references in 9 components, against @vue/compiler-sfc 3.5.43.

SQL. SQLFluff 4.4.0's semantics over one generic dialect for PostgreSQL, SQLite, MySQL and ANSI, parsed by DerekStride's tree-sitter-sql 0.3.11 with Rerail's patches (native/grammars/tree-sitter-sql/PATCHES.md). Where dialects differ, PostgreSQL wins.

  • Names fold as in PostgreSQL: naked to lower case, quoted exact.
  • Scope: query blocks (scope query). SELECT, UPDATE, DELETE, INSERT bind FROM/JOIN relations (form relation: alias, else the table name's last part) and the target table (target); a WITH binds CTE names (cte).
  • Resolution: a column's table qualifier resolves in its block or an enclosing one (SQLFluff's RF01, AL05); a CTE only through a relation selecting from it. resolves.unresolved: a SELECT qualifier nothing binds (RF01). binds: { used: false }: a relation unused in its block and nested ones (AL05).
  • Values: literals only where PostgreSQL and SQLite agree; type refused (PostgreSQL's pg_typeof and SQLite's typeof name different types). compare reads values and names; key, member, reference and structural modes are refused (use tokens).
  • Arguments of an invocation bind as in PostgreSQL 18.6's parser: by position, then name (name => v, name := v); extract, position, trim in PostgreSQL's operand order. Signature markers, syntactic and estree are refused.
  • Refused: calls (routine bodies are other languages, $$ … $$, PL/pgSQL; a .sql file has no workspace call graph) and formatArgs (ISO SQL has no format function; PostgreSQL's format() and SQLite's printf() are extensions). No SQLFluff rule reads either.
  • Suppression: -- noqa (suppress.sqlfluff). No parse grammar, no languageOptions.

Rust. Names resolve lexically, as rustc does, from syntax alone (Rust Reference, "Names"). Macro token trees, macro_rules! bodies, and anything needing types or expansion are not read.

  • Visibility: items in their whole block or module (extern functions and statics too); let and pattern bindings from where made; generics and for<'a> lifetimes in their item or type.
  • Shadowing: patterns shadow functions and lowercase imports, never constants, unit structs or capitalised imports, which rustc's naming makes a constant, a struct or a variant (use Ordering::{Less, Greater}).
  • Isolation: a nested fn sees no outer locals; a module only its parent's macros. Types, values, macros, lifetimes and labels are separate namespaces.
  • Item macros (thread_local!, lazy_static!, bitflags!: any but std's expression macros) and glob imports may define names, so an otherwise unbound name is not unresolved.
  • resolves.import: crate paths (std::env::var, crate::m::f). Heads go through the file's use and extern crate items, a use's own head where it stands (use crate::b as a; use a::f; imports crate::b::f). Cycles, and heads a glob or item macro may bind, give no path.
  • self::, super:: normalise to crate:: paths of the file's module, placed by the host's path under the crate's src/.
  • Values: literals as rustc evaluates them, through operators, casts and const blocks: suffix-typed integers of any width, floats, char, strings, byte and C strings. follow reads the file's const items as their declared type. Past 256 nesting levels: unknown.
  • value.type: bool, char, &str, &[u8], &CStr, integer and float types; none for an unsuffixed number.
  • Arguments: positional.
  • Calls: crate functions by path, Self::f/Type::f via the crate's impl blocks, self.m() via the enclosing impl. Open: other method calls, trait dispatch, closures, function pointers; Some/Ok/Err where a glob may bind them; calls into a crate with a #[path] module.
  • Macros: unparsed, so their calls are open, never absent. That covers any macro but std's formatting, assertion and constructor macros (println!, format!, assert!, vec!, matches!, ...), and those holding a call (println!("{}", f())).
  • Formats: rustFormat trees; formatArgs style rust reads format_args! macros as rustc 1.99.0 binds them.
  • Suppression: suppress.clippy reads rustc and Clippy lint-level attributes and #[clippy::msrv].
  • Refused: languageOptions, resolves.imported, compare modes over property names, references, names and structures, arguments' signature markers and modes syntactic/estree, other families' grammars and format styles.

Evaluation pipeline #

For each file in a clause's scope, the engine:

  1. picks the grammar matcher, skipping the file if when, file or the language fail;
  2. narrows nodes to candidates via the rule's anchor plan;
  3. matches the rule object at each candidate: three-valued (true, false, unknown);
  4. applies the soundness gate to files with syntax errors;
  5. drops suppressed violations and renders the rest.

The stateless evaluator (CompiledCodeRuleDsl.evaluate, sessions) and the indexed workspace (CodeRuleDslWorkspace) share every stage; the engine's tests run both paths.

Budgets. Exceeding maxVisitedNodes, the work budget, a deadline or utility depth 256 fails the clause for the file with budget-exceeded, never a false verdict. maxWitnesses, an output cap, fails it with witness-limit.

  • Scaled: in the workspace, shared work (parsing, tape, anchor index) and each clause's allowance grow with file size. Visits: maxVisitedNodes or maxVisitsPerNode (16) per node, whichever is more.
  • Isolated: each clause selects its roots and runs under its own allowance; one that runs out fails alone, reported as a coverage gap, not a failed audit. Fix: simplify the rule, or exclude generated or vendored files from its scope.
  • Ceiling: one evaluation of a file may spend eight allowances; a clause that finds them spent fails without running.
  • Caching: running out while evaluating all of a file's clauses is stored. A failure that depends on what else ran (the ceiling, exhausted shared work, a partial evaluation) is not; a later workspace retries it.

Rule objects and term order #

A rule object's keys are terms; all must hold (an implicit all). A rule object with no matcher key is refused. Terms run in a fixed order (compile/ast_rule.rs), since a term can bind captures later terms read:

  1. Atomic terms: pattern, kind, regex, capture, parse, nthChild (without ofRule), arguments.
  2. The ordered group: nthChild with ofRule, all, any, not, matches, relations (inside, has, precedes, follows), binding terms (resolves.binding / resolves.write, binds), formatArgs. A term reading a sibling's capture runs after it (a stable topological sort, compile/order.rs); mutual reads are refused. See Captures.
  3. Late terms: count, compare, layout, value; then resolves (but binding/write), which binds and reads nothing; then importTarget, which binds nothing and reads other files.
  • Explicit all keeps written order: reading a capture only a later item binds is refused ("move all/2 before all/0") unless bound before the all.
  • host runs last among a parse tree's terms.
  • Kindless rules (no kind or pattern) are accepted, unlike upstream ast-grep. They test every node, including anonymous tokens (==, ,, default): the only way to report a token.
  • Abstract kinds (grammar supertypes such as expression) match the nodes the parser reported as their members.
  • Refused: Python pattern variables that are no metavariable ($At).

Comments #

Grammars keep comments in the tree as comment nodes: match by kind, read by regex (delimiters included). Exceptions:

  • TypeScript, TSX, JavaScript add html_comment (<!-- and --> lines).
  • Blade, Vue: the template's comments; under ast.embedded, the program's (Blade, Vue).
  • Rust: line_comment and block_comment; a doc comment has an outer_doc_comment_marker or inner_doc_comment_marker child and a doc_comment text child.

Elsewhere, tell line, block and doc comments apart by their opening, with regex:

Position. A comment is a tree-sitter extra: a child of the node whose span holds it, in source order. A comment before a declaration is its preceding sibling, so use sibling relations, not inside or has:

  • Leading: follows: { stopBy: "neighbor", kind: "comment" } on the node, or precedes: { stopBy: "neighbor", kind: … } on the comment. In TypeScript, a comment before export function f precedes the export_statement, not the function_declaration. stopBy: { not: { kind: "comment" } } skips a run of comments.
  • Attached (no blank line after): layout: { after: { to: "token", blank: { eq: 0 } } }. Trailing (code before it on the line): layout: { before: { to: "token", breaks: { eq: 0 } } }. See layout.
  • Inside: inside and has reach only comments within a node's span. Python puts a comment indented after a block's last statement in the block; at the outer indentation, in the outer list.
  • Counted by nthChild, count, kindless rules and $$$ captures. Add not: { kind: "comment" } where one could stand.
  • Skipped by arguments, formatArgs, calls, and compare's index and structure, as their linters do.

Text. A regex group anchors a violation (capture.NAME) but binds nothing compare reads. Capture the comment (pattern: "$C"), derive text with a transform, and put the compare inside the relation binding the other side (it binds from its first match). Directive comments parse into trees: eslintDirective, phpDoc.

Another language. Comments named comment need no engine change: only a style row above and a case in matcher/comments_tests.rs. Other names (line_comment, block_comment, as in Rust and Java) also go into the predicates' filters (child.kind() != "comment" in matcher/, calls/, literal/). An embedding language (Blade over PHP) keeps each grammar's comments in its own document.

Rerail's own comment. rerail-ignore silences the rules it names, by id, at the node it covers, regardless of the rule or the repository's suppressions setting (Rerail's comment). suppress reads other linters' comments only where a violation opts in and the setting is honour (the default).

Limits. rerail-ignore works where an ast query reports: forbid witnesses, a select_when's select, require_each subject rows, and a budget group's violation at its first row in path order. It never removes facts other violations read: evidence rows, counted budget rows, the exists side, calls seeds. regex witnesses (file.content, file.path) have no tree and stay unsuppressed.

2. Grammar #

The accepted JSON, production by production. Each production says in one line what it is; open it to see its keys, one per line, each with its type and what it does. key? is optional, a nested object is indented under its key, and an object refuses any key it does not list. A key's name links to the card in section 3 that explains it. A | B are alternatives, Str a non-empty string, NAME a capture name ([A-Z0-9_]+, written without $); "list of T" is a JSON array and "map of K to V" an object used as a map. A note under a production is a rule the schema adds (at least one key, one form, per-language keys).

For tools and AI agents: every production is in this page's HTML, open or closed. The same grammar is published as a JSON Schema, rerail.policy.v1.schema.json, generated from src/engine/code-rule/code-rule-schema.ts (zod), which the engine's host validates rules with; the hosted docs also serve this page as Markdown (code-rule-dsl-reference.md). The script scripts/generate/docs/code-rule-dsl-reference.mjs check checks every data-zod annotation names an object in that file and that its documented keys match.

relational #

Joins projected AST facts across files with read-only SQLite queries, and reports each row its final query returns.

In the grammar: Clause, Evidence

  • inputs: 1–32 named evidence relations, each a table of its projected fields plus __path, __start and __end. Filter with SQL and recursive stages, not evidence where or closure.
  • stages: up to 64 tables computed in order, each a SELECT or a batched reachability over the inputs and earlier stages.
  • query: the final SELECT. Its path, start_byte and end_byte name an input witness, an eligible syntax node, or a declared file-start location. Other columns are finite JSON scalars, read as variables.row.
  • partitionBy: "file" runs each file on its own: inputs and stages see one file, findings are cached per file, and an edit invalidates its file's result. The default "repository" joins facts across files.

Queries
Single read-only SQLite SELECT statements without parameters, each checked against empty tables before any source is read. Stages
Materialized in order, with bounded index statistics; inputs and stages are released after their last reader. Reachability
reachability: { roots, edges, batchSize?, graph? } replaces query and indexes. roots selects __path,id and edges __path,src,dst, both reading inputs and earlier stages. Text functions
rx_matches(text, pattern) tests a Rust regex; rx_extract(text, pattern, group) returns a group or null; rx_replace(text, pattern, replacement) replaces every match. Patterns and replacements obey maxRegexPatternBytes. source_text(path, start_byte, end_byte) reads an immutable source slice in the active snapshot; unknown paths, null arguments, negative, reversed or out-of-range offsets and split UTF-8 characters give null. References

Results
An input's anchor sets its __start and __end, so a row names that input witness exactly. key names 1–16 fields giving each finding a stable identity; duplicate identities fail evaluation. code names the field supplying the diagnostic code.
Suppression
Suppression removes only the findings whose anchors it covers; input facts stay and keep supporting other findings.
Work
Shares the input-scaled work allowance: one unit per input row, 256-byte regex chunk, or 64 SQLite VM instructions. Recursive queries and result collection obey work limits and interruption; incomplete inputs or exhausted work fail explicitly.

Names and bindings

Two keys read the file's scope table, built on first use once per file revision and reading (Python version and typing settings, TypeScript block scoping, stub files). resolves asks what a reference resolves to; binds asks about a binding's name node.

Python follows Ruff 0.16.9's semantic model; TypeScript, eslint-scope and typescript-eslint 8.70.1's scope manager. Resolution is lexical and per file: no flow, types or other files.

Resolution reads the binding the scope table picks. Python: module and class bodies see only earlier bindings (an assignment's value first, a comprehension's element after its clauses); function and lambda bodies resolve after the whole module; global/nonlocal redirect; star imports never shadow; an unconditional del unbinds by order; string type definitions are forward references. TypeScript: var hoists to the nearest function, module, namespace or static block; let, const, classes and function declarations bind in their block (from ES2015); a JSX tag is a reference when it starts upper case.

Sub-grammars

A string literal or comment can be a small language of its own: a printf-style format, a str.format template, a type in a string, an ESLint directive.

parse decodes the literal, parses it with a sub-grammar, and matches a rule of that grammar's kinds on the tree's root. Each parsed node maps back to its source bytes, so a capture inside the tree can anchor a violation, carry a fix range, or be enumerated by each.

Source mapping of a parsed string (literal/offsets.rs). Each decoded character keeps its source span: an escape maps to the whole escape, \r\n to both bytes, a line continuation to nothing; implicit concatenation chains the parts. A node spans its first character's start to its last character's end. An annotation tree maps exactly, by a shift, for a simple string (one part, its source its value), and every node to the whole string otherwise. An eslintDirective tree maps each node to its exact bytes in the comment.

parse #

4. Unknown and soundness #

How a rule decides when the file alone cannot, and which rules still run on files with syntax errors.

The three-valued model #

A term's verdict is true, false or unknown. Unknown means the file alone cannot decide; see the sources below.

  • At the root, unknown is no violation.
  • Under not it stays unknown, so a negated rule never reports what it could not decide.
  • Only clauses that read values or usedness can be unknown. Every other rule matches exactly as two-valued ast-grep would.

Sources of unknown:

  • value on an expression it cannot decode.
  • compare in the value, member, structural and transform-of-value readings.
  • arguments in language mode past a starred argument or **kw.
  • The usage filters of binds and resolves.binding under locals(), a dynamic __all__, a direct eval or with.
  • parse and formatArgs on literals they cannot read.
  • nthChild.ofRule over an unknown sibling.

Budgets are never unknown or false: running out fails the clause for the file (budget-exceeded).

Soundness under syntax errors #

tree-sitter recovers from syntax errors with ERROR and zero-width MISSING nodes. The engine drops every witness whose range meets an error region, so claims about nodes inside a witness read only cleanly parsed source.

A metavariable met again after it is bound must match the same text (ast-grep's repeated metavariable). A capture name is [A-Z0-9_]+; in Python patterns only such names are metavariables.

Ordering rules #

  • Atomic terms bind first and never read a relation's capture.
  • The ordered group is a stable topological sort (compile/order.rs). A term that reads a capture runs after every sibling that binds it, unless an atomic term bound it already; otherwise terms keep ast-grep's order. Reading means a comparison side, a within, what a not would bind, a transform variable's roots, or a gap's target.
  • Late terms read everything bound before them.
  • any reads what any branch reads, even where another branch binds the name.
  • matches binds what its utility binds, inside another utility too. A call binds and reads its parameters by the caller's names.
  • host reads the host captures as they stood when its parse, or the embedded around it, began (an atomic term): not a sibling relation's, and none under ast.embedded. It binds nothing; compare a host capture with an inner one inside it.
  • embedded's rule sees no host capture; what it binds is exported to the host rule.

Pitfalls #

  • A relation that binds stops at an unknown candidate. If only existence matters, write count: { ..., "min": 1 }, which searches on.
  • A relation binds the first node its walk reaches: has in document order, inside outwards, precedes forwards, follows backwards. A later sibling's comparison sees only that binding. Enumerate with each, or move the comparison into the relation's rule so the walk goes on to the first node whose captures compare.
  • An explicit all is a sequence. Write the binder first; the compiler refuses the reverse.
  • Negation reads. A not naming a capture a sibling binds tests the bound value; a not with a fresh name binds nothing outward.
  • A frame's captures are its own. A message cannot name $YP bound inside a parameterized utility; return it through a parameter.
  • Python dict literals in port generators ({**base, "not": …}) drop a repeated key before any JSON exists. The engine refuses repeated keys only in raw JSON and YAML.
  • A fix after a $$$ capture that can end in a line comment lands inside the comment.

6. Known limits #

Deliberate boundaries and measured gaps, grouped by area. None is an open bug.

Matching, ordering and budgets

  • Kindless rules test every node, anonymous tokens included: add kind unless the rule targets a token. An abstract kind matches only the nodes the parser reported as its members, which depends on position.
  • With a zero-width node in the file, the sibling check is quadratic in one container's siblings; it crosses the 500 ms budget at several thousand.
  • Atomic terms run first and never read a relation's capture; the ordered group sorts by dependency; terms reading each other's captures are refused. The all order check refuses only misorders it can prove: a binding outside the rule object excuses a conflict.
  • A binding relation's search ends at the first unknown candidate no other term makes false. all goes on past an unknown term; terms mentioning its would-be captures stay open.
  • each reaches what a first-match search reaches by skipping reported bindings, not bindings needing two sub-rules to change together.
  • Utility recursion: depth 256 or 1 MiB of stack (a debug build runs out after roughly 60 hops); each hop spends a step. At most 1,024 distinct parameterized calls per query and grammar.
  • A fix outside its witness is dropped, not widened.

Names and bindings

  • Resolution is lexical and per file: no flow-sensitive bindings, types, other files or TypeScript import resolution. An unconditional Python del unbinds by order (Ruff's Deletion); a conditional one does not.
  • A name has a value only via a binding that carries one: plain or annotated assignment, walrus, an unpacked name paired with a display element, a TypeScript single-definition declarator nothing writes. Bindings are flow-insensitive; at most 16 names per decode. ESLint's ReferenceTracker follows every write; Rerail models only the effectively constant case.
  • resolves binds a name at the reference's position. Ruff resolves some checks elsewhere: annotations at the call site, B008 defaults and RET503/F811 at the body or module end, SIM220–223 over the whole bool-op.
  • In a Python scope declaring a name global, it is never a global match. Python 2's print >> x is a keyword token, not a print reference. Notebook builtins are not modelled; only unresolved knows __path__.
  • A walrus in class bases binds in the enclosing scope (Ruff: the class's type scope); in a deferred annotation, after the module (Ruff: after function bodies too). A comprehension read after the code that follows it reads its names at one position.
  • In a stub, a callee or subscript in a function body resolves against imports before the function (Ruff reads bodies after the module).
  • Usedness is unknown under Python locals() or a dynamic __all__ (Ruff reports F401 there), and for TypeScript bindings a direct eval or with can see.
  • Python only: latest, outer. TypeScript only: occurrence, builtin, redefines.every, directives on a filter, write, file.declaration, lib, private forms.
  • only counts the bindings the table records (Ruff also counts a builtin it materialized). binds has no only; stopAtGlobal is resolves.binding's alone. redefines compares forks by the innermost branch; ports approximate Ruff's TYPE_CHECKING dominance and @overload by qualified name. A nonlocal binding redefines nothing.
  • Private names are bindings of binds only. tree-sitter-typescript 0.23 does not parse accessor fields.
  • Python identifiers are NFKC-normalized wherever names are resolved or compared, as in CPython and Ruff (𝒞 is C, F821_28). Kept as written: string contents (__all__ entries, **{…} keys, format fields), violations, spans, regex, source/tokens text, and names a code rule lists.
  • ast-grep's matcher compares pattern identifiers and twice-bound metavariables by source text, so $X == $X misses 𝒞 == C; use compare with structure. ECMAScript and PHP names compare as written. Identifier tests use Rust's current Unicode tables, newer than esutils'.
  • Declared TypeScript globals are ESLint's configured globals plus, with lib, typescript-eslint's lib variables (none without lib). readonly/writable are not told apart. Among conflicting /* global */ comments, off wins; ESLint takes the last.
  • sloppyFunctions models strictness, not which calls bind this. parserOptions reads only globalReturn and impliedStrict.
  • resolves.imported reads a relative module by text only. seenBefore places deferred annotations, string annotations and a stub's class bases where written. A dotted name qualifies nothing; file.module cannot tell a dotted name from two names.

Values, arguments and comparison

  • TypeScript folds only the allow-listed builtin calls in calls.rs. Not folded: new, non-builtin functions, transcendental Math, Object.keys/values/entries, Date, Symbol, Map/Set, URI functions, toExponential, callback methods, an array's or object's ToPrimitive.
  • Python folds nine builtin constructors (not frozenset); no % formatting, complex division or powers.
  • Unknown by design: f-strings with a field, unknown \N{…} names, lone surrogates, Python ints past 4,096 bits and BigInts past 128, strings past 64 KiB, nesting past 256.
  • value holds only on expressions. key is ESLint core's (a nameless key equals no key). member is unknown wherever a key does not fold, so "both unknown" is never equal (typescript-eslint's hasOverloadSignatures calls it equal).
  • tokens compares leaf texts, not token types. JavaScript orders follow the relational operators while eq stays Object.is (null <= 0 but not eq); no loose-equality mode.
  • arguments has no variadic slot and ignores arguments without a slot. estree has no "every argument equals the parameter at its index" form.
  • The structural modes are Python's. structure-parts reads parts only at the top of a capture. Comments are ignored (SIM114 compares them separately).
  • JSX attribute strings decode as in typescript-estree, but tree-sitter-typescript's JSX string grammar rejects an entity name with a digit (&sup2;). JSX text has no value.

Sub-grammars, layout, transforms and suppression

  • parse holds on literal nodes only and reads only str literals; f-strings with a field, t strings and bytes are unknown. braceFormat reads one level of nested fields. Where Ruff and CPython differ, the grammars follow Ruff. Python re patterns are not parsed; ecmaRegex is not planned.
  • Rules run over host documents only: Ruff's expression rules inside string type definitions need a port's parse: annotation. One witness per host node, so a port reports one undefined name per string (with each, one per capture). Type comments and doctests are not read. Three differences in semantic syntax errors of complex strings remain.
  • eslintDirective has no items for eslint and eslint-env comments; a setting lies outside its item's range; an item's resolves takes global alone.
  • A host rule binds nothing outward and cannot read a sibling relation's capture.
  • An embedded program's fix applies only where its range lies in one stretch copied from the file. Ranges over bytes the lowering wrote (an interpolation's parentheses, PHP Blade's wrapping of directive arguments) carry no fix.
  • embedded reads a language's one via, and its rule sees no host capture. Compare host and program captures inside a host rule, or in the host rule after embedded exports them.
  • layout reads lines, not columns; a token is a tree-sitter leaf; blank treats the file's edge as a token; a layout on a parsed node is false. curly's isCollapsedOneLiner ends a body before a trailing ;, which span counts.
  • With bare \r line endings, tree-sitter-python's comment token swallows the code after it (a grammar gap).
  • transform has no rewrite, string form, length or arithmetic. Variables compare as text only; value converts scalars only. A transform of a regex group is text computed per witness, so no comparison reads it. ${NAME} is Rerail's (ast-grep renders it literally).
  • count counts a $$$ capture's named nodes, not its comments or line continuations; it cannot count a relation's matches.
  • nthChild and index count tree-sitter's named children and commas; field names tree-sitter's fields.
  • suppress is opt-in, applied at the anchor's start. Not modelled: ESLint's unused-directive reports and configuration comments, Ruff's range suppressions, RUF100, code redirects, UnusedPsalmSuppress, phpcs:set.

Configuration, reuse and the catalog

  • Language options are per ast query: scoring one port under many configurations compiles a variant per configuration. typingModules/extendGenerics build a table per setting. when gates on configured values only. file.inPackage reads whether the host sent a module path.
  • A parameterized call passes captures only. A frame's captures are not the query's, and the query's transform is not readable in a frame.
  • A shared utility compiles with the languageOptions of each query that reaches it; its all order conflicts are settled only where it is called.
  • Options resolve before validation, and a gated query is still compiled, so every reference must be valid in every configuration. cases keys numbers by JavaScript's String(n) (1.0 selects "1"); integral option numbers beyond ±(253−1) are refused.
  • Grammar gaps: tree-sitter-python 0.25 has no PEP 810 lazy imports. tree-sitter-typescript 0.23 does not parse using declarations and misparses f<T>`…` and a few ASI-dependent lines. tree-sitter-vue (ce8011a) reads two value-less shorthands in a row (:a :b) as one attribute and a dotted end tag (</A.B>) as a syntax error.
  • A Vue script in a language other than JavaScript or TypeScript (coffee) embeds no program; a template in pug or with a src embeds none of its expressions.
  • An older Rerail breaks on a newer catalog row (the strict codeRuleSchema), since one ~/.rerail/rerail.sqlite serves every worktree; no tolerant read is done.

8. Not included #

Features the DSL deliberately leaves out.

The ECMAScript regex grammar is not part of the DSL. It would add parse with grammar: "ecmaRegex" (a port of regexpp) for ESLint's regex rules. Those rules are of low product value, the port would be about 3,000 lines of Rust, and the ESLint suite never ported them.

  • ecmaRegex is refused ("not supported yet").
  • The TypeScript parse plumbing it would need exists in a minimal form, built for eslintDirective.

Also not planned:

  • flow-sensitive bindings;
  • per-file select_when;
  • cross-file analysis and types;
  • shared utilities across documents.
