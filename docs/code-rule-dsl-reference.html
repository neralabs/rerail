Rerail code-rule DSL reference

Every construct of rerail.policy/v1: the rule keys, relations, combinators and predicates the native engine compiles, with their JSON shape, semantics, capture behaviour, three-valued behaviour, soundness under syntax errors, language support and limits, each mapped to rules committed in the Ruff, ESLint and TSLint conformance suites and the bundled code rules.

Milestone M13 of the Rerail code-rule DSL engine

Sources of truth. Accepted JSON: src/code-rule-schema.ts (zod) and src/code-rule.ts (types). Semantics: native/src/code_rule_dsl/; the since badges name the engine's development milestones (M0 to M13 and their fix rounds). Every example below is either quoted from a code-rule document (its path and JSON pointer are printed above it; Ruff and ESLint ports come from conformance suites that are not part of this repository) or written for this page; each one that is not marked fragment compiles with the engine at this commit (scripts/code-rule-dsl-reference.mjs examples).

1. Overview #

Documents, clauses, violations #

A code-rule document is one JSON object: a format (always "rerail.policy/v1"), an id, a positive integer revision, an optional description, an optional scope (path globs the code rule applies to) and a non-empty list of clauses. The catalog stores one document per row of ~/.rerail/rerail.sqlite; every top-level field is a column, which is why every construct added since M7 lives inside clauses.

A clause has an id unique in its document and exactly one form:

FormWhat it holdsWhat it reports
forbida query: ast, regex, or select_whenone violation per witness (per binding with each)
require_eachtwo evidence relations, subject and evidenceeach projected subject without evidence
budgetan evidence relation, group_by keys and count.ltegroups over the budget
llmanything (the schema reads unknown)reserved
defineshared utils, options and confignothing: it has no violation; a document needs a clause beside it

Every clause but a define carries a violation spec: a code, an anchor, a message template and optionally a fix, each and suppress. What Rerail does with a violation is the document's mode: log records it, steer reports it to the agent, and block is delivered like steer until block enforcement lands. A violation's fix is a suggestion: Rerail never applies it.

Almost all rules are forbid clauses over an ast query: a language, a rule object matched on every candidate node of a file, and the query options around it (utils, constraints, transform, languageOptions, when, file). The rule object is ast-grep 0.45.3's rule language, which Rerail runs through the pinned ast-grep-core, plus Rerail's extensions: name resolution, values, arguments, sub-grammars, layout, counting and comparison.

The languages come from the language registry (languages/*.json, see docs/language-packs.md). rust, sql and vue are planned: a code rule may name one and is stored, but compiling it is refused with the code language-not-supported, and the catalog keeps it inactive until the engine reads the language. A predicate whose capability a language has not-supported-yet is refused the same way; one it has refused is invalid.

Language support #

Rerail follows one language standard: a code-rule language names the dialects its rules compile for, while a family supplies semantic behavior. Structural terms (kind, pattern, regex, relations, field, nthChild, count, layout and matches) work in every dialect. A term unavailable to a family is refused at compile time by the engine and zod, with its path and code-rule language.

It resolves class, function and constant names as PHP-Parser's NameResolver does (resolves: { import, prefix }) and variables through a flow over PHP's control flow: resolves.unresolved holds where no path defines a read (PHPStan's variable.undefined), resolves.global names superglobals, resolves.binding and binds read PHP's forms (assignment, augmented, for, except, parameter, global, static) and scopes (global, function, closure), and usage as Psalm's unused-variable analysis does; what the dynamic symbol table decides is unknown. PHP reads PHP-only files, while .blade.php templates use Blade.

PHP's compare reads keys (key, member), names (name), references (reference, reference-no-static-keys) and structures (structure, structure-hash) as nikic/PHP-Parser 5.9.0 parses the code and PHP 8.5 converts and looks up names (see the modes); arguments with mode: "syntactic" finds a slot by name, else by position before the first unpacking, as Ruff's find_argument reads PHP-Parser's args. PHP refuses structure-parts (it has no implicit string concatenation) and mode: "estree" (ESLint's node.arguments of ESTree).

PHP's printf-family formats are printfFormat trees, read as PHP 8.5.11's php_formatted_print reads them, and formatArgs with style printf reads sprintf, printf, fprintf and the v*printf calls as PHP and PHPStan's argument.sprintf do. sscanf/fscanf formats are scanfFormat trees, read as PHP 8.5.11's ValidateFormat reads them, and style scanf reads those calls' variables. PHP's doc comments are phpDoc trees, phpstan/phpdoc-parser's AST as PHPStan 2.2.16 reads it: tags, types, variables and descriptions. Python's format grammars and styles are refused on PHP with their counterpart named; annotation is refused because PHP holds no type in a string (its declared types are syntax, and its PHPDoc types are phpDoc).

Blade answers every semantic predicate but suppress on the PHP its template embeds, read as PHP reads it (the language standard): the view is the program illuminate/view 13.34.0's BladeCompiler compiles the template to (echoes, the arguments of the directives it compiles, @php blocks, <?php ?> tags and bound component attributes, in the template's control flow), each node spanning the template bytes it came from. A Blade rule names Blade's kinds and PHP's alike; where both grammars name one (comment), it is Blade's, so parse: { grammar: "phpDoc" } over the embedded doc comments names no kind. A pattern Blade reads as plain text (sprintf($F, $$$A)) is parsed as PHP and matches the embedded program; a contextual one whose selector picks a metavariable is refused. Blade's $loop, $message, $value and @inject variables are defined where Blade defines them. Unknown: view data at the template's top level (Blade's caller passes it), any variable after @props or @aware, a node holding a token Blade writes that the template does not spell (the !( of @unless), and calls through $this, self:: or static:: at the top level. Refused, naming blade and why, as on PHP: structure-parts, mode: "estree", stopAtGlobal: false, resolves.write, sameImport, exported, builtin, directives, Python's format grammars and styles, annotation and languageOptions. The oracle (fixtures/blade/view/) checks 212 regions, 78 PHPStan reports over 154 reads and 49 constant expressions across 19 templates; over the 128 Laravel templates 14257 of 14257 copied bytes agree.

Evaluation pipeline #

For each file a clause's scope admits, the engine picks the query's grammar matcher (skipping it where when, file or the language do not hold), narrows the file's nodes to candidates through the rule's anchor plan, matches the rule object at each candidate with three-valued verdicts, applies the soundness gate for files with syntax errors, drops suppressed violations, and renders the rest.

The stateless evaluator (CompiledCodeRuleDsl.evaluate, sessions) and the indexed workspace (CodeRuleDslWorkspace) share every stage; each milestone's tests run both paths. Budgets (maxVisitedNodes, maxWitnesses, deadlines, utility depth 256) fail a clause for the file with budget-exceeded, never as a false verdict.

Rule objects and term order #

A rule object holds one or more terms (its keys); all must hold, as an implicit all. A rule object with no matcher key is refused. The engine runs the terms in a fixed order (compile/ast_rule.rs), because a term can bind captures that later terms read:

  1. Atomic terms, in this order: pattern, kind, regex, capture, parse, nthChild (without ofRule), arguments.
  2. The ordered group: nthChild with ofRule, all, any, not, matches, the relations (inside, has, precedes, follows), the binding terms (resolves.binding / resolves.write, binds) and formatArgs. A term that reads a capture a sibling binds runs after it (a stable topological sort, compile/order.rs); two terms that each read what the other binds are refused. See Captures.
  3. Late terms: count, compare, layout, value, then resolves (except binding/write), which binds and reads nothing and so runs last, after every cheaper test.

An explicit all keeps its written order: an item that reads a capture only a later item binds is refused at compile time ("move all/2 before all/0"), unless something binds the name before the all runs. A parse tree's host term runs last among its rule object's terms.

A rule with no kind or pattern ("kindless") is accepted, unlike upstream ast-grep, and tests every node including anonymous tokens (==, ,, default); that is the only way to report a token. An abstract kind (a supertype no node carries) is refused.

3. Constructs #

One card per construct. Each gives the JSON shape; the semantics; how it composes with other terms; what it binds or reads (captures); how it behaves when a verdict is unknown; whether a rule using it is evaluated in a file with syntax errors (sound: witnesses outside error regions are reported and the file gets a source-partial failure; source-incomplete: the clause is not evaluated on the file); which languages take it; its limits; and one to three example rules with their source. Section 4 explains the verdict model and the syntax-error classification in full.

Document and queries

format · id · revision · mode · description · scope · clauses #M0

The document's envelope. scope names the files the code rule reads: repository-relative globs (globset), include non-empty, exclude applied after. Without a scope the code rule reads every file (include: ["**"]).

Shape
{ "format": "rerail.policy/v1", "id": Str, "revision": Int≥1, "mode": "log" | "steer" | "block", "description"?: String, "scope"?: { "include": [Glob]⁺, "exclude": [Glob] }, "clauses": [Clause]⁺ }
Semantics

mode is what Rerail does when any of the document's clauses reports: log records the violation for review and never sends guidance, steer sends it to the agent, and block is reserved for enforcement and is delivered like steer until that lands. Clause ids are unique within the document. At least one clause is not a define. $option references anywhere but format, id, revision and the defines' options/config are resolved before the document is validated (options); the catalog stores the resolved document. A repeated object key anywhere in raw JSON or YAML is refused ("duplicate key", with its JSON pointer) since M6.

CompiledCodeRuleDsl.inScope(path) answers with the same matcher evaluation uses, so a host hands the code rule only the files it will read.

Syntax errors
n/a: the envelope reads no source.
Languages
any; a document may hold clauses of both languages and regex clauses.
Limits
An older Rerail that shares ~/.rerail/rerail.sqlite cannot read a row whose document uses a key newer than it (codeRuleSchema is strict); every key since M7 carries this risk.

forbid · require_each · budget · llm #M0

A reporting clause holds exactly one form and a violation. forbid reports every witness of its query. require_each reports each projected subject evidence row without an evidence row. budget counts projected evidence rows per group_by and reports groups past count.lte. llm is reserved.

Shape
{ "id": Str, "violation": Violation, "forbid": Query } { "id": Str, "violation": Violation, "require_each": { "subject": Evidence, "evidence": Evidence } } { "id": Str, "violation": Violation, "budget": { "query": Evidence, "group_by"?: [Str], "count": { "lte": Int≥0, "distinct"?: [Str] } } } { "id": Str, "violation": Violation, "llm": any }
Semantics
  • A forbid violation may use any anchor, a fix (over an ast or file.content regex query), each and suppress (over an ast query). The violation of a select_when query reads its select side.
  • require_each, budget and llm violations take only anchor: "witness.span" and no fix.
  • An evidence relation wraps an AST query, gives its rows an as alias, and projects non-empty fields from captures or file metadata. Its optional where predicate compares projected alias.field operands.
Syntax errors
as the evidence query.
Languages
any language supported by the wrapped AST query.
Limits
Evidence queries are AST-only; project is required and must name at least one field.

ast · regex · select_when #M0

A query has exactly one source. ast matches a rule object on a language's syntax tree; regex runs a Rust regex over the file's text (file.content) or its path (file.path); select_when reports its select query's witnesses where its exists query has at least one witness anywhere in the workspace. Cross-file clause forms use Evidence, not a query source.

Shape
{ "ast": { "language", "rule", "utils"?, "constraints"?, "languageOptions"?, "when"?, "file"?, "transform"? } } { "regex": { "source": "file.content" | "file.path", "pattern": Str } } { "select_when": { "select": Query, "exists": Query } }
Semantics
  • regex: every match is a witness; named groups ((?<NAME>…) or (?P<NAME>…)) are the witness's captures, which messages, anchors and (for file.content) fix templates read. A file.path match is no source text, so it takes no fix.
  • select_when: exists is global by design; the violation reads select's captures.
  • The ast query's options: utils, constraints, transform, languageOptions, when, file.
Captures
regex: named groups. ast: metavariables and the other binding terms.
Syntax errors
regex: always sound (only AST leaves mark a file partial). ast: per rule, see each construct.
Languages
ast: python, typescript, javascript, php, or blade. regex: any file.
Limits
Pattern and regex source sizes are bounded by the capabilities (maxAstPatternBytes, maxRegexPatternBytes: 16 KiB each in the bundled capabilities).

Names and bindings

Two keys read the file's scope table, built once per file revision (and per reading: Python version and typing settings, TypeScript block scoping, stub files) on first use. resolves asks what a reference resolves to; binds asks about a binding's name node. Python follows Ruff 0.16.9's semantic model; TypeScript follows eslint-scope and typescript-eslint 8.70.1's scope manager. Resolution is lexical and per file (tiers 1 and 2 of the M7 plan): flow, types and other files are out of scope.

Resolution reads the binding the scope table picks. Python: module and class bodies see only bindings made earlier (evaluation order: an assignment's value first, a comprehension's element after its clauses); function and lambda bodies are resolved after the whole module; global/nonlocal redirect; star imports never shadow; an unconditional del unbinds by order; string type definitions are read as forward references. TypeScript: var hoists to the nearest function, module, namespace or static block; let, const, classes and function declarations bind in their block (from ES2015); a JSX tag is a reference when its first character is upper case.

Sub-grammars

A string literal or a comment can itself be a small language: a printf-style format, a str.format template, a type written as a string, an ESLint directive. parse decodes the literal, parses it with a sub-grammar into a tree of its own, and matches a rule of that grammar's kinds on the tree's root. Every parsed node maps back to the source bytes it came from, so a capture inside the tree can anchor a violation, carry a fix range, or be enumerated by each.

The mapping M11a records (literal/offsets.rs): each decoded character keeps the source span it came from; an escape maps to the whole escape, \r\n to both bytes, a line continuation to nothing, and implicit concatenation chains the parts. A node covers its first character's start to its last character's end. An annotation tree maps exactly by a shift for a simple string (one part, its source its value) and maps every node to the whole string otherwise; an eslintDirective tree maps each node to its exact bytes in the comment.

4. Unknown and soundness #

The three-valued model #

Since M9a a term's verdict is true, false or unknown. Unknown means the engine cannot decide from the file alone: a value it does not know, a slot a starred argument may fill, a usedness a dynamic scope may hide, a key that does not fold. At the root, unknown is no violation; under not it stays unknown, so a negated rule never reports what it could not decide. Only clauses that read values or usedness touch the flag, so every other rule matches exactly as two-valued ast-grep would.

CombinatorVerdict

Budgets never read as unknown or false: running out fails the clause for the file (budget-exceeded).

5. Captures #

What binds, what reads #

A metavariable already bound when a pattern meets it again must match the same text (ast-grep's repeated metavariable). A capture name is [A-Z0-9_]+; in Python patterns only such names are metavariables.

Ordering rules #

  • Atomic terms bind first and never read a relation's capture. The ordered group is a stable topological sort (compile/order.rs): a term that reads a capture (a comparison side, a within, what a not would bind, a transform variable's roots, a gap's target) runs after every sibling that binds it, unless an atomic term bound it already; otherwise the terms keep ast-grep's order. Late terms read everything bound before them.
  • An any reads what any branch reads, even where another branch binds the name. A matches binds what its utility binds, inside another utility too; a call binds and reads its parameters by the caller's names.
  • A host rule reads the host captures as they stood when its parse began (an atomic term): not a sibling relation's.

Pitfalls #

  • A relation that binds stops at an unknown candidate. Where only existence matters, write count: { ..., "min": 1 }, which searches on.
  • Which node a relation binds first is the walk's order (has in document order, inside outwards, precedes forwards, follows backwards). A later sibling's comparison sees that one binding, not every candidate; enumerate with each or move the comparison into the relation's rule (the walk then goes on to the first node whose captures compare).
  • An explicit all is a sequence. Write the binder first; the compiler refuses the reverse.
  • Negation reads. A not naming a capture a sibling binds tests the bound value; a not with a fresh name binds nothing outward.
  • A frame's captures are its own. A message cannot name $YP bound inside a parameterized utility; return it through a parameter.
  • Python dict literals in port generators ({**base, "not": …}) drop a repeated key before any JSON exists; the engine refuses repeated keys only in raw JSON and YAML.
  • A fix after a $$$ capture that can end in a line comment lands inside the comment.

6. Known limits #

Consolidated from "Known limits after M12's fix round" and the milestone records, grouped by area. Each is a deliberate boundary or a measured gap, not an open bug.

Matching, ordering and budgets

  • Kindless rules test every node, anonymous tokens included; add kind unless the rule targets a token. Abstract kinds are refused.
  • The sibling check in a file with a zero-width node is quadratic in the siblings of one container (crosses the 500 ms budget at several thousand siblings).
  • Atomic terms run first and never read a relation's capture; the ordered group is sorted by dependency; two terms reading each other's captures are refused. The all order check refuses the misorders it can prove, not every one: a binding outside the rule object excuses a conflict.
  • A relation whose rule binds ends its search at the first unknown candidate no other term makes false; all goes on past an unknown term, but terms mentioning its would-be captures stay open.
  • each reaches the bindings a first-match search reaches by skipping reported ones; bindings that need two sub-rules to change together are not reached.
  • Utility recursion: depth 256 or 1 MiB of stack (a debug build runs out after roughly 60 hops); each hop spends a step. At most 1,024 distinct parameterized calls per query and grammar.
  • A fix outside its witness is dropped rather than widened.

Names and bindings

  • Resolution is lexical and per file: flow-sensitive bindings, types and other files are out of scope, and so is TypeScript import resolution. Python's unconditional del unbinds by order (Ruff's Deletion); a conditional one does not.
  • A name has a value only through a binding that carries one (a plain assignment, annotated assignment or walrus, an unpacked name paired with a display element; a TypeScript single-definition declarator nothing writes). Bindings are flow-insensitive; at most 16 names per decode. ESLint's ReferenceTracker follows every write; Rerail models only the effectively constant case.
  • resolves binds a name at the reference's own position; Ruff resolves some checks from another site (annotations from the call site, B008 defaults and RET503/F811 from the body or the module's end, SIM220–223 from the whole bool-op).
  • In a Python scope that declares a name global, the name is never a global match. Python 2's print >> x is a keyword token, never a print reference. Notebook builtins are not modelled; __path__ is known to unresolved only.
  • A walrus in a class's bases binds in the enclosing scope (Ruff: the class's type scope); a walrus in a deferred annotation binds after the module (Ruff: after the function bodies too). A comprehension read after the code that follows it reads its names at one position.
  • In a stub, a callee or subscript inside a function body is recognized by the imports made before the function (Ruff reads bodies after the module).
  • Python usedness is unknown under locals() and a dynamic __all__ (Ruff reports F401 there); TypeScript usedness is unknown for bindings a direct eval or a with can see. latest/outer are Python's; occurrence, builtin, redefines.every, directives on a filter, write, file.declaration, lib and private forms TypeScript's.
  • only counts the bindings the table records (Ruff also counts a builtin it materialized); binds has no only; stopAtGlobal is resolves.binding's alone. redefines compares forks by the innermost branch; Ruff's TYPE_CHECKING dominance and @overload by qualified name are approximated by ports. A nonlocal binding redefines nothing.
  • Private names are bindings of binds only; tree-sitter-typescript 0.23 does not parse accessor fields.
  • Python identifiers are NFKC-normalized wherever a name is resolved or compared, as CPython and Ruff read them (𝒞 is C, F821_28). String contents (__all__ entries, **{…} keys, format fields), violations, spans, regex, source/tokens text and the names a code rule lists stay as written. A pattern's identifiers and a metavariable bound twice compare source text in ast-grep's matcher, so $X == $X misses 𝒞 == C; use compare with structure. ECMAScript and PHP names compare as written. Identifier tests use Rust's current Unicode tables, newer than esutils'.
  • Declared TypeScript globals follow ESLint's configured globals and, with lib, typescript-eslint's lib variables; no lib means none; readonly/writable not told apart; among conflicting /* global */ comments off wins where ESLint takes the last.
  • sloppyFunctions models strictness, not which calls bind this. parserOptions reads only globalReturn and impliedStrict.
  • resolves.imported reads a relative module by text only; seenBefore places deferred annotations, string annotations and a stub's class bases where they are written. A name with a dot qualifies nothing; file.module cannot tell a dotted name from two names.

Values, arguments and comparison

  • TypeScript folds the allow-listed builtin calls calls.rs implements; not new, non-builtin functions, transcendental Math, Object.keys/values/entries, Date, Symbol, Map/Set, URI functions, toExponential/toPrecision, callback methods; an array's or object's ToPrimitive. Python folds nine builtin constructors (not frozenset), no % formatting, no complex division or powers.
  • Unknown by design: f-strings with a field, unknown \N{…} names, lone surrogates, Python ints past 4,096 bits and BigInts past 128, strings past 64 KiB, nesting past 256.
  • value holds only on expressions. key is ESLint core's (a nameless key equals no key); member is unknown wherever a key does not fold, so "both unknown" is never equal (typescript-eslint's hasOverloadSignatures reads it as equal). tokens compares leaf texts, not token types. JavaScript orders follow the relational operators while eq stays Object.is (null <= 0 but not eq); there is no loose-equality mode.
  • arguments has no variadic slot and ignores arguments without a slot; estree has no "every argument equals the parameter at its index" form.
  • The structural modes are Python's; structure-parts reads parts only at the top of a capture; comments are ignored (SIM114 compares them separately).
  • A JSX attribute string decodes as typescript-estree does; tree-sitter-typescript's JSX string grammar rejects an entity name with a digit (&sup2;). JSX text has no value.

Sub-grammars, layout, transforms and suppression

  • parse holds on a literal node only and reads str literals only (f-strings with a field, t strings and bytes are unknown); braceFormat reads one level of nested fields; the grammars are Ruff's where Ruff and CPython differ. Python re patterns are not parsed; ecmaRegex is not planned.
  • Rules run over host documents only; Ruff's expression rules inside string type definitions need a port's parse: annotation. One witness per host node, so a port reports one undefined name per string (with each, one per capture). Type comments and doctests are not read. Three differences in semantic syntax errors of complex strings (see M11a's fix round).
  • eslintDirective has no items for eslint and eslint-env comments; a setting lies outside its item's range; an item's resolves takes global alone. A host rule binds nothing outward and cannot read a sibling relation's capture.
  • layout reads lines, not columns; a token is a tree-sitter leaf; blank treats the file's edge as a token; a layout on a parsed node is false. curly's isCollapsedOneLiner ends a body before a trailing ;, which span counts.
  • Files with bare \r line endings: tree-sitter-python's comment token swallows the code after it (a grammar gap).
  • transform has no rewrite, no string form and no length or arithmetic; a variable compares as text only; value converts scalars only; a transform of a regex group is text computed per witness, so no comparison reads it. ${NAME} is Rerail's (ast-grep renders it literally). count gives a $$$ capture's named nodes but comments and line continuations; no count of a relation's matches.
  • nthChild and index count tree-sitter's named children and commas; field names tree-sitter's fields.
  • suppress is opt-in and applied at the anchor's start; ESLint's unused-directive reports, configuration comments, Ruff's range suppressions, RUF100, code redirects, UnusedPsalmSuppress and phpcs:set are not modelled.

Configuration, reuse and the catalog

  • Language options are per ast query; a harness scoring one port under many configurations compiles a variant per configuration. typingModules/extendGenerics build a table per setting. when gates on the configured values only. file.inPackage reads whether the host sent a module path.
  • A parameterized call passes captures only; a frame's captures are not the query's; the query's transform is not readable in a frame.
  • A shared utility is compiled by each query that reaches it; its all order conflicts are settled only where it is called. Options are resolved before validation and a gated query is still compiled: every reference must be valid for every configuration; cases keys numbers by JavaScript's String(n) text (1.0 selects "1"), and an integral option number beyond ±(253−1) is refused.
  • tree-sitter-python 0.25 has no PEP 810 lazy imports; tree-sitter-typescript 0.23 does not parse using declarations, misparses f<T>`…` and a few ASI-dependent lines. Vue single-file components are not parsed.
  • An older Rerail breaks on a newer catalog row (the strict codeRuleSchema), since one ~/.rerail/rerail.sqlite serves every worktree; a tolerant read is not done here.

Glossary

Witness
A node (or regex match, or fact row) a query's rule matched; one violation per witness, or per binding with each.
Candidate
A node the anchor plan hands to the rule: the rule's root kinds, narrowed by text probes; every node for a kindless rule.
Term
One key of a rule object; the terms of an object form an implicit all, run in the order of Rule objects and term order.
Capture, metavariable

Span capture, export
A capture a parsed tree (parse, formatArgs.missing) hands to the host: decoded text plus the host range it came from.
Frame
The environment of a parameterized utility call: only its parameters, fresh captures per level.
Grammar gap, dialect
A kind, field or pattern one dialect of a language (TypeScript, TSX) cannot express; the rule compiles for the other and fails only when no dialect can.
Unknown
A verdict the engine cannot decide from the file: no violation, negated or not.
source-partial
A failure a sound clause reports on a file with syntax errors: it ran, and witnesses outside the error regions stand.
source-incomplete
A failure an unsound clause reports on a file with syntax errors: it did not run there (or a cross-file source was incomplete).
budget-exceeded
A failure when a clause runs out of maxVisitedNodes, maxWitnesses, utility depth or its deadline on a file; never a false verdict.
Scope table, usage index
The per-file bindings and references a language's scope rules produce (M7), and the reads each binding receives (M10), built lazily once per file revision and reading.
Module path
A Python file's dotted module (the host's module, a string or a list of names as on disk), else its stem; it qualifies definitions and resolves relative imports.
Port, suite
A code-rule document that reproduces another linter's rule (Ruff, ESLint, typescript-eslint, TSLint), scored by a conformance suite against the linter's own fixtures (PASS, PARTIAL, BLOCKED; TP/FP/FN).
Fixture-fit
A port that passes its fixtures through a hand-written approximation that is wrong on unusual forms; the engine features replaced many.
Oracle
An upstream tool (Ruff 0.16.9, ESLint 10.11.0, typescript-eslint 8.70.1, eslint-utils 4.10.1, CPython 3.13, ast-grep 0.45.3) whose output, generated offline and committed, pins a semantics.
