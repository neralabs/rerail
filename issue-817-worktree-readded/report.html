A worktree made again is read as soon as Git lists it

1. The one question

May the walk of a repository's other worktrees watch the folder where Git registers them, so that a change Git makes there starts a walk?

We recommend: approve it: a file written in a worktree made again reaches the Log within seconds where it waited for an unrelated change, and the watch starts no Git process of its own.

6. The decisions

What tells the walks that Git lists a worktree again?

We chose a watch of the folder where Git registers the worktrees: any add, remove, move, repair or prune changes it.

Would change our mind: A Git that rewrites an entry's gitdir or locked file on ordinary commands: each would ask for a walk.

When is a worktree whose watch ended watched again?

We chose at once when another folder stands at its path (device, file number, birth time); the same folder waits as before.

Would change our mind: A file system that gives a folder made again the same file number and birth time.

Where does the registry watch take its room on Linux?

We chose only room the watch budget has left, folders above it included, given up to a worktree that needs it.

Would change our mind: A user whose engine runs at its budget and who would rather have the registry watched than the budget kept.
