5. The changes

Each line opens its card.

ASession start says itMedium riskStarts that say nothing is recorded: 0 of 6 at main, 6 of 6 here.
Problem
A person who turned autostart off starts a session while no daemon runs. Rerail records and checks nothing in it. Claude Code's and Cursor's start hooks answer {}. Claude Code's footer and Codex's start line say not running, with no cause.
Who meets it
Every session start under RERAIL_AUTOSTART=0 or false with no daemon. Since #503, on main and in no published version, false keeps hooks from starting one too. How many people set the variable is not known. Source: #660.
What it does
answerAutostartOff turns the failure of a session's start into an answer with the line rerail status prints, only when autostart is off and no daemon runs. Any other hook or failure is rethrown. runClaudeHook and runCodexHook return the line as systemMessage. runCursorHook returns cursorRelayedLine's request to the agent. Two docs pages and the unreleased release note say so.
Risk
Medium. It changes what a session is told, and in Cursor what the agent is asked to say. A wrong guard would answer a real failure as if it were the person's choice.
Check
Does answerAutostartOff rethrow everything but a session start's AutostartOffError? In runCodexHook the new catch sits inside the old one: a daemon gone for any other reason must still give Rerail ✕ not running. runHostHook still logs no failure for an off autostart. Claude Code sends a session start on a resume, /clear and a compaction too, so the line shows again there.
BError text names the settingLow riskOff-autostart error under false: names RERAIL_AUTOSTART=0 at main, RERAIL_AUTOSTART=false here.
Problem
The error a hook gets when autostart keeps it from a daemon names RERAIL_AUTOSTART=0 whatever the person set. With autostart on, the error for a late-answering daemon of another package names it too.
Who meets it
A person who reads the hook failure log, a hook's stderr or rerail events: under false, or with autostart on while another package's busy daemon answers late. With change A, none of #660's six starts prints either error.
What it does
daemonEngineEndpoint writes the setting as set into the no-daemon error. otherPackageDaemon writes it into the other-package error only when autostart is off. With autostart on that error reads "the running Rerail daemon is from another Rerail package; run rerail daemon stop, then rerail daemon start".
Risk
Low. Error text only: when each error is thrown does not change, and the hooks decide as before.
Check
Can either error print undefined? The no-daemon error is thrown only after the lookup an off autostart makes, so the setting is 0 or false there. otherPackageDaemon names the setting only under autostartOff. This change is three commits (bcb467316, 89513b9f0, fea0d916d) and four test cases. Tell us, and it leaves as its own pull request.

Limits that stay.

  • Later hooks, the hook failure log, rerail status, when a daemon starts, and Codex's not running line for any other cause stay as on main.
  • The line shows at every session start while the daemon stays down. Nothing remembers that it was said.
  • Whether a person in Cursor reads the line depends on the agent following the request.
  • With autostart off and no daemon, a session's start no longer writes its error to stderr: the line replaces it. RERAIL_ENGINE_SOCKET, which that error named, stays in docs/reference.md.
  • On Windows, with autostart off, a start whose recorded engine pipe another program holds now answers with the line, where main rejected. claude-hook.test.ts pins it. Off Windows that start still fails for the daemon that does not answer.
  • Pi and OMP sessions start their daemon whatever the setting says, so they record and get no line.
  • A script that matches the old error text meets new words. No rule file, API, pack or stored data changes.
