6. The decisions

What decides when the engine on the pipe has no proof?

We chose the process's start against startedAt, a fact the system keeps and #677 already reads.

Would change our mind: a way to read the pipe's server process from Node, which would prove the holder directly.

8. What is not covered

  • macOS never ran; it asks no proof, so the change does not reach it.
  • An elevated daemon met from a terminal that is not was never run: our test machines' sessions run elevated. The code drops its record, as main does.
  • The uninstall through the product was not run beside a 0.1.4 daemon; a seam case shows its stops use the read that loads no engine, within the stop's 10 s.
  • A late answer through the product (a 0.1.4 daemon that answered only after a hook's start looked) was not run; a seam case covers it.
One smaller gap, two limits that stay
  • The engine start beside an older engine with no record. With daemon.json already gone, as after 0.1.5 met such a daemon, a start runs a second daemon on a fallback pipe, at main and here: the engine start has no record to weigh a start against.

Limits that stay.

  • rerail status beside a 0.1.4 daemon takes 0.2 s on Windows 11, 1 s just after an update. Once, on a cold disk, the engine's load used its 2 s: status said not answering, and kept the record.
  • A daemon of 0.1.4 or earlier whose start cannot be read, or that this user may not signal, is handled as at main: its record goes and a hook launches its own daemon.
