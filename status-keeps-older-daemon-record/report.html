6. The decisions

What decides when the engine has no proof, and what is that daemon sent?

We chose the record's release, then the process's start; it is sent nothing with the token and ended through its process.

Would change our mind: a way to read the pipe's server process from Node, which would prove the holder directly.

8. What is not covered

  • macOS never ran; it asks no proof, so the change does not reach it.
  • An elevated daemon met from a terminal that is not was never run: our test machines' sessions run elevated. The code drops its record, as main does.
  • Constrained Language Mode by a machine policy is on no test machine; the uninstall's end runs in that mode in its case, set in its own session.
  • Off autostart, Codex and Cursor beside a 0.1.4 daemon ran through the product at earlier heads; seam cases cover them here.
One smaller gap, two limits that stay
  • The engine start beside an older engine with no record. With daemon.json already gone, as after 0.1.5 met such a daemon, a start runs a second daemon on a fallback pipe, at main and here: the engine start has no record to weigh a start against.

Limits that stay.

  • A daemon of 0.1.4 or earlier whose start cannot be read is kept as not answering, and sent nothing; a hook launches no second daemon beside it.
  • The ends wait on the process's handle; only an end that hangs meets the stop's 5 s bound.
