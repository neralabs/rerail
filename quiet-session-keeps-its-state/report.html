Decision report · Rerail pull request #680

Sessions: a quiet session's close frees its memory and takes nothing else

1. The one question

Does a session closed without its end lose anything but the memory #503 frees?

  1. A quiet session stays open and owned; one never ended reads as live. Changes the intent.
  2. A steer owed at a stop, restart or day's close arrives at the next event. Changes the intent.
  3. A daemon holds a lock in locks/owners/; a later one ends a dead daemon's sessions.

We recommend: answer #675 first, and if a quiet session is to stay open, approve this: beside main on Linux x64 and Windows 11 no case came out lower, except the cost #675's comment names.

5. The changes

Each line opens its card.

AA quiet session stays liveHigh riskQuiet 30 minutes: ended on main, live and scannable here; 18 cases fail on main.
Problem
Since #503 a session quiet for 30 minutes is closed as its end would, though its agent is often still open. The dashboard shows it ended, a scan for it fails, and another program's change to its files goes unrecorded.
Who meets it
Anyone whose agent stays open through 30 quiet minutes. On one developer machine, 13 of 70 Claude Code sessions in 7 days went 30 minutes or more without a transcript line, then went on. No published version has the close.
What it does
closeIdleSession frees the session's memory and answers with an IdleClose. #markClosed and #endOwnership leave the record open and the owner claimed. The engine service keeps a SessionSuspension, and resumeSuspended opens the session for a queued scan. walkResume and #restoreHeldTexts let the next walk go on where the last stopped. The daemon's stop ends each suspended record at its quiet time.
Risk
High. A session's end time, its owner and its Log entries change. A suspension that leaks keeps the memory #503 frees, and one that loses track of its owner leaves a scan queued for good.
Check
Can a session be out of memory and out of the service's suspended map with its record still open? #suspend keeps the suspension before any await. resumeSuspended asks again inside the lane, so an end that ran first stays an end. In closeSession, endedAt is null only while suspending is set. #owesAgent counts a queued scan and a running checkout audit. #baselinePath compares a source held before the suspension with its last observation, though the first walk is a baseline.
BOwed steers wait in the ledgerHigh riskA steer owed across a restart: lost on main, sent at the next event here.
Problem
A steer or held finding a session has not delivered when it closes without its end is dropped. The agent never learns that its edit broke a rule, or that Rerail rolled an edit back.
Who meets it
A session open at a daemon stop or restart, in 0.1.4 too, and one quiet for a day while it owes a steer. On main's source 3 cases fail on it. How often in the field is not known.
What it does
At a close without the end, #owedAtClose takes the steers and held findings no newer revision overtook, and #keepOwed writes them as one owed ledger entry with the digest of each file they name. owedForDisk scrubs it. At the next event #takeOwed gives the steers and writes the entry again, emptied. A Merge Assist note stays with Merge Assist (ownSteers).
Risk
High. It decides what the agent is told, hours after the edit it speaks of, and it writes steer text to a file in the checkout.
Check
Can a steer go out twice, or after its file changed? #takeOwed takes only once #stillOwed has compared each file with its digest, and gives none once the session closed meanwhile. collectDeliveries now runs in the session's lane. A rolled-back edit's steer goes out all the same. owedFinding withholds the message and fix of a finding in a secret-like file. A session that holds only a Merge Assist note is freed at 30 minutes, where main kept it a day.
CA dead daemon's sessions endHigh riskA killed daemon's session, its process id reused: owned for good on main, ended here.
Problem
A daemon that ends without its stop ends none of its sessions. When another process gets its process id, each reads as owned: a scan for it stays queued and its next event is refused, so its edits go unchecked.
Who meets it
Anyone whose daemon is killed, hits its heap limit or dies with the machine. Keeping a quiet session open (A) adds every suspended session to those a dead daemon leaves. Windows gives a process id out again soon.
What it does
Each engine service holds a system lock on a file in locks/owners/ for its life (holdOwnerLock), and its owner tokens begin with the lock's id. At a start and each minute, endSessionsOfEndedOwners ends each open session whose writer ended (writerEnded): record at its last event plus 30 minutes, owner released, scans interrupted. forgetFreedOwnerLocks removes the files no open session names.
Risk
High. A wrong verdict ends a live session and interrupts its scans, or leaves a dead daemon's session owned, so its next event is refused and its edits go unchecked.
Check
Can writerEnded call a running daemon's session ended? A lock that is held, has no file or cannot be tried reads as held. A row with no lock that names the judging process is its own only while its token is in claimsHereWithoutLock, with no clock read. registerOwner clears an end time a sweep wrote just before the claim. forgetIfFree removes a lock file only while holding its lock, once no open session's row names it.

8. What is not covered

  • A session whose end never comes reads as live: #675's question.
  • No maintainer has reviewed it or answered #675.
  • Rows that name no lock (Pi, OMP, another database, an earlier version) go by process id, as on main.
  • The cost measurements were not run again at 94f8302a3.
  • macOS never ran.
Six smaller gaps, eight limits that stay
  • #675's steps by hand were not run: its numbers are from the tests.
  • Two lines have no case, by choice: the guard of failScans in resumeSuspended, reached only if the open fails after the owner claim was taken back, and server.close inside the try of close(), which fails only for a server not listening.
  • Pi and OMP runtimes were not driven through NativeSessionServer at 94f8302a3: the probe makes the lockless owner claim their runtime makes, in the service's own process. CI's OMP and Pi real-session runtime paths job passes.
  • How often in the field: 13 of 70 sessions is one developer machine, and a gap in a transcript stands in for a gap between hooks. The rate across installs is not known.
  • The whole unit set on our machines last ran at 961848254, before the last fourteen commits. One Windows case of code-rule-runtime-lifecycle.test.ts failed beside other runs and passed when its file ran alone. CI ran the whole set at d724d2090.
  • One test of audit-cli.test.ts timed out once on a loaded Linux machine and passed 12 of 12 runs alone, here and at main. It is main's own, in its Git verdicts (#692), and this pull request does not touch it.

Limits that stay.

  • A session whose end never comes (a killed agent, a SessionEnd hook that timed out) reads as live until its daemon stops. The dashboard and rerail settings show it live, and rerail reset keeps its row.
  • A suspension keeps about 45 KB per session more than main until the daemon stops: Linux x64, a repository of 100 worktrees of 300 Python files, 3 sessions one after another.
  • With 200 sessions open, the check at a start and each minute takes about 3 ms on Linux x64 and 15 to 36 ms on Windows 11, on the daemon's main thread; main takes under 0.4 ms.
  • A daemon that could take no owner lock, and any daemon for a session it records in another database, ends a quiet session at the idle close, as main does. The owed steers still wait in the ledger.
  • A stopped daemon's lock file stays in locks/owners/ until the next start or sweep removes it.
  • A scan for a suspended session starts once its rules have compiled again.
  • A session's end still drops what it owed, and an owed steer whose file changed while the session was closed is dropped.
  • Passing the lock to Pi and OMP runtimes means editing NativeSessionServer#initialize, at cyclomatic complexity 10 on main: a refactor first, in a pull request of its own.

9. What we ask of you

Asks 1 to 3 rule on answers 1 to 3.

  1. On #675: a session closed without its end: ended, kept open, or kept open a day? We recommend kept open, as built.
  2. May an owed steer reach the agent at its next event, hours later? We recommend yes: dropped if its file changed.
  3. May each daemon hold a lock file in locks/owners/ for its sessions? We recommend yes: process ids are reused.
