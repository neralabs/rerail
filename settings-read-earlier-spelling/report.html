6. The decisions

Should the earlier rows be read where they are, or copied to the stored key?

We chose reading them at lookup, as the maintainers chose on #666: small, no storage change, and deleted once 0.1.4 is gone.

Would change our mind: Installs still on 0.1.4 after the next releases, so that the lookup could never be deleted.

8. What is not covered

  • Two settings stay lost a status line hidden in a folder opened in another letter case, and a rule turned off outside Git through a mapped or subst letter or 8.3 name.
  • A Git checkout through a re-pointed letter takes the Log mode 0.1.4 saved through that letter, as 0.1.4 did: no record says whose row it is. Outside Git the folder's own repository decides.
  • macOS and Linux read the same keys as main; Linux x64 ran the tests, macOS never ran.
One smaller gap, two limits that stay
  • A spelling the daemon cannot see (a mapped or subst letter of another logon session, as for an elevated daemon) costs 4 to 7 file calls every event, with main's answer. Keeping a failed lookup per spelling ends that; a letter mapped later then waits for the daemon's restart.

Limits that stay.

  • Under another letter case, 0.1.4's next start or stop there decides, as at main: 0.1.4 compares Windows paths without letter case.
  • A session already open when 0.1.4 stops a folder outside Git through a mapped letter keeps showing Rerail on in its status line.
