Node.js pack: ships all 24 of its eslint-plugin-n rules, judged on the Node test set (239 real files from open-source history at the commit that introduced each violation, with eslint-plugin-n's own findings, and 222 copies fixed by hand) as well as on the plugin's own tests. `n-hashbang`, `n-no-deprecated-api`, `n-no-exports-assign` and `n-no-process-exit` start on, as the plugin's recommended configurations turn them on; the other 20 start off. `n-hashbang` now also reports a byte order mark or a CR LF line ending on a bin file's shebang, `n-no-deprecated-api` reports `export * from` a module once for each deprecated member it re-exports, and the rules that reach CommonJS names through scope read each file's module system as the plugin's configs do, by extension and package.json `type` alone (a `type`-less package.json, or none, is CommonJS, whatever the file's syntax). `n-callback-return` does not report a function's final `callback?.()`, which the plugin reports only because its last-statement exemption misses an optional call (declared in `divergences.json`).

The pack is now recommended for a repository with a Node.js server framework (`express`, `koa`, `fastify`, `@hapi/hapi`, `@nestjs/core`, `restify`, `@adonisjs/core`, `sails`, `@feathersjs/feathers`, `moleculer`) or `electron` dependency, or with `.cjs`, `.mjs`, `.cts` or `.mts` files outside tests, scripts, fixtures and configuration. An `@types/node` dependency, which browser projects carry for their tooling, no longer recommends it.

Two more eslint-plugin-n rules are ported as candidates, scored on the plugin's tests but not shipped yet: `n-no-unpublished-bin` (a file package.json lists as a bin executable that npm leaves out of the package) and `n-no-top-level-await` (a top-level `await`, `for await` or `await using` in a file npm publishes), both reading what npm publishes from package.json `files`, `.npmignore` and `.gitignore` as the plugin does.
