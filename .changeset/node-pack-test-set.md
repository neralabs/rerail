Node.js pack: ships 33 eslint-plugin-n rules, judged on the plugin's own tests and on real-code samples, among them 323 real files from open-source history at the commit that introduced each violation, labelled with eslint-plugin-n's own findings, and 279 copies fixed by hand. Seven start on, as the plugin's recommended configurations turn them on: `n-hashbang`, `n-no-deprecated-api`, `n-no-exports-assign`, `n-no-process-exit`, `n-no-unsupported-features-es-builtins`, `n-no-unsupported-features-es-syntax` and `n-no-unsupported-features-node-builtins`; the other 26 start off.

New ports since the last release: `n-no-unsupported-features-node-builtins`, `-es-builtins` and `-es-syntax` (a Node.js API, ECMAScript built-in or syntax that a Node.js version in the package's `engines.node` range lacks), `n-prefer-global-crypto`, `n-prefer-global-timers`, `n-prefer-import-assert-strict`, `n-prefer-process-get-builtin-module`, `n-no-top-level-await` (in a file npm publishes) and `n-no-unpublished-bin` (a bin file npm leaves out of the package, read from package.json `files`, `.npmignore` and `.gitignore` as the plugin reads them). `n-no-restricted-import` and `n-no-restricted-require` are candidates: upstream restricts nothing by default, and the port's `restricted` option takes regular expressions.

`n-hashbang` now also reports a byte order mark or a CR LF line ending on a bin file's shebang, `n-no-deprecated-api` reports `export * from` a module once for each deprecated member it re-exports, and the rules that reach CommonJS names through scope read each file's module system as the plugin's configs do, by extension and package.json `type` alone (a `type`-less package.json, or none, is CommonJS, whatever the file's syntax).

The pack is now recommended for a repository with a Node.js server framework (`express`, `koa`, `fastify`, `@hapi/hapi`, `@nestjs/core`, `restify`, `@adonisjs/core`, `sails`, `@feathersjs/feathers`, `moleculer`) or `electron` dependency, or with `.cjs`, `.mjs`, `.cts` or `.mts` files outside tests, scripts, fixtures and configuration. An `@types/node` dependency, which browser projects carry for their tooling, no longer recommends it.
