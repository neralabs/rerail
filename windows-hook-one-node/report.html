Decision report · Rerail pull request #656

A Claude Code hook on Windows runs in one Node

1. The one question

With another node first on PATH, does each Claude Code hook event on Windows run in one Node, and every other setup keep main's entry?

  1. Where set-up's PATH finds another node, the hook entry starts cmd.exe. Changes the intent.
  2. One setup then costs more per event than main. Changes the intent.
  3. A late hook failure on the node entry exits 0.

We recommend: rule first on #655's open question (is a cmd.exe hook entry acceptable there, or do you prefer another way), since this pull request builds the cmd.exe entry and changes to whatever you prefer.

5. The changes

Each line opens its card.

AThe cmd.exe hook entryHigh riskNodes per event where PATH finds another node: 2 at main, 1 here.
Problem
Where the first node on PATH is not the Node that ran set-up, every Claude Code hook event starts two Nodes: the launcher on PATH's, the hook in the recorded one. With no node on PATH, no hook starts.
Who meets it
A Windows computer whose first node on PATH is another file, on every hook event. One started 1,615 launchers and 1,615 hook processes in 15 minutes of sessions (#655). How many installs have such a PATH is not known.
What it does
hookExecEntry asks pathFindsNode. Where PATH finds the recorded Node it writes main's node entry. Elsewhere execHookEntries writes System32's cmd.exe with cmdHookArgs, each word an argument of its own, but only when isFullWindowsPath holds, a file is there and cmdReadsAsOneWord passes every path. launcherArgs and isWindowsCmd read both forms back.
Risk
High. It is the command of every Rerail hook Claude Code runs there, in src/setup/, a high-risk path. A wrong entry starts nothing, or a file the repository holds. A wrong read-back takes a person's own hook.
Check
cmdHookArgs: can a path with a space, & or % reach cmd.exe split? /d skips AutoRun, and NoDefaultCurrentDirectoryInExePath keeps the fallback node.exe to PATH. isWindowsCmd asks only for cmd.exe in a folder named System32, with no file check, so an entry whose cmd.exe has gone is still replaced; cmdLauncherArgs then requires Rerail's exact words. Could a person's own hook pass both? execHookEntries tests the path's form before it looks for the file.
BA failing hook's answerMedium riskOwn-process answers like a child's, of seven hooks: 2 at main, 7 here.
Problem
The cmd.exe entry runs every hook in the launcher's own process. There main keeps a failing hook's exit code, which Claude Code shows as a hook error, or answers no {}, or adds {} after an answer.
Who meets it
At main, a Windows computer whose PATH finds the recorded Node, when a hook fails after it has loaded. With the cmd.exe entry, every computer this fix reaches. Source: seven hooks started through each entry on Windows 11.
What it does
watchAnswer wraps process.stdout.write and notes any write of one character or more. An exit listener calls quiet when the code is not 0: it names the code on stderr, writes {} only when nothing was written, and sets exit code 0. The catch around the import asks watchAnswer too. The check after the import goes.
Risk
Medium. The answer Claude Code gets from a failed hook changes on main's node entry too: exit 0 where it kept the hook's code. A wrong count writes {} after a real answer, or none.
Check
Does every answer a hook writes go through process.stdout.write? One written straight to file descriptor 1 would count as silent and get {} after it. In the exit listener, does {} always reach the pipe before the process ends? The five cases pass on Windows and Linux. A native crash or an out-of-memory abort never reaches the listener and keeps its code.
CThe connected checkLow riskCoding-agent tests failing over the code of main, Linux x64: 3. Here: none.
Problem

Who meets it
Anyone on Windows whose shell or daemon runs with another PATH than set-up did, each time they open the dashboard or run rerail status. Source: the test of either form, which read updated before keepHookCommand.
What it does
connection plans its dry run with keepHookCommand, the platform it is asked about and fileExists. keptHookEntry in harness-registration.ts keeps the entry the settings hold when it runs the same launcher, Node and hook in either form. A cmd.exe entry with no file at its path is not kept, so it reads as out of date and a refresh replaces it.
Risk
Low. A dry run that writes nothing. A wrong answer shows Claude Code as connected, or not, in rerail status and the dashboard. Set-up and rerail update leave the option off.
Check
Only connection passes keepHookCommand in src. keptHookEntry returns the other form only when the settings hold exactly that command and those arguments (holdsHookEntry), so an entry a person has edited is not taken for current. Is a cmd.exe entry whose file has gone the only one that must read as out of date?

Would change our mind: an answer on #655, a window shown for cmd.exe, or a policy that refuses its line.

8. What is not covered

  • Not run: a real Claude Code event through the cmd.exe entry.
  • Not measured: DisableCMD, a policy that blocks the command prompt; set-up still writes the cmd.exe entry.
  • One setup costs more than main: set-up's PATH finds another node, Claude Code's the recorded one. About 10 to 17 ms and 8 MB more per event.
  • Going back to an older Rerail needs rerail install --remove first; the release note says so.
  • No person has reviewed it, only the automated reviewer.
Six smaller gaps, eight limits that stay
  • Why no real event ran. CI's job with real Claude Code sessions runs on macOS only, and no Windows machine the tests ran on has Claude Code. The end-to-end test starts the entry with no shell, a hidden window and the event on stdin.
  • What DisableCMD could cost. cmd.exe is present on such a computer, so set-up writes the cmd.exe entry. Whether Windows then refuses its cmd /d /c line was not run. The node entry of main does not go through cmd.exe.
  • The mirror setup stays as on main: two Nodes per event where set-up's PATH finds the recorded Node and Claude Code's finds another.
  • The default file read on Linux. No Linux test pins the default read of cmd.exe's file to the computer's own files: a default that never finds cmd.exe passes every Linux test. Only the Windows end-to-end test fails on it, in CI's Windows unit job.
  • The one Windows 11 failure. test/hosts/claude/claude-status.test.ts failed one test in the 18-file run at eb88b0dee, beside 5 other test runs. It runs no code this change edits, and main fails it under load too (#681).
  • Outside CI, macOS and the whole test suite did not run at this head. Linux and macOS registrations are the same, file for file, at main and here. CI ran the suite on Linux and windows-2025, and its job with real sessions on macOS.

Limits that stay.

  • Going back to an older Rerail needs rerail install --remove at this version first: an older set-up adds its node entry beside each cmd.exe entry, so each hook runs twice.
  • An older Rerail's removal leaves the cmd.exe entries, which exit 1 on every event once its install is gone. Claude Code shows a hook error and goes on.
  • Where SystemRoot gives cmd.exe no full path, or no file is at that path, set-up writes main's node entry, word for word, with its two Nodes where PATH finds another.
  • A launcher, Node or hook path that cmd.exe would split keeps main's node entry too: one with %, ! or a double quote, or one with no space that holds &, a bracket or another cmd.exe operator.
  • One cmd.exe per event stays where the entry starts it: 8.5 MB of working set, measured at the tree of dcf577dda.
  • When Claude Code gives up on a hook it ends cmd.exe, and Windows leaves the Node running. The hook then ends itself once its parent is gone, as it does under main's launcher.
  • In the launcher's own process a native crash or an out-of-memory abort keeps its exit code. Claude Code shows it as a hook error and does not block on it; docs/threat-model.md says so.
  • Linux and macOS registrations, Codex, Cursor, OMP, Pi and the status line are as on main.

9. What we ask of you

Asks 1 to 3 rule on answers 1 to 3.

  1. On #655: is a cmd.exe hook entry acceptable, or do you prefer another way? We recommend an answer there; this pull request follows it.
  2. May set-up's PATH choose the form, though one setup then costs more than main? We recommend yes: only the person's commands write their settings.
  3. On the node entry, may a late hook failure exit 0 with no hook error? We recommend yes: the child path of main already does.
